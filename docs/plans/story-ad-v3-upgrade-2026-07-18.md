# 剧情广告 V3 大版本升级说明

> 日期：2026-07-18
> 目标：在不影响通用行业、通用业务和既有项目查看能力的前提下，把剧情广告从“按场景合成长母片”升级为“编辑镜头优先、连续性受控、费用先授权”的通用视频生成架构。

## 1. 核心原则

1. 默认一个编辑镜头对应一个生成单元，不再因为场景相同就自动合成长母片。
2. 只有用户明确选择“一镜到底”，并且模型能力允许时，才合并多个镜头生成。
3. 人物连续性与场景连续性分别建模，不再用“同场景”替代“同人物、同空间、同时间”的判断。
4. 无人物、单人、双人、多人/群像都使用同一份领域协议，通过人物模式和调度信息表达差异。
5. 单场景和多场景都拆成“场景世界 → 场景访问 → 编辑镜头 → 生成单元”，允许返回同一场景而不丢失连续性。
6. 任何付费视频提交前必须展示并确认成本上限；模型价格未知时禁止提交。
7. 付费视频默认不自动重试。失败后保留诊断信息，由用户确认后再重试。
8. 后端错误统一向用户输出中文；原始技术错误只进入服务端日志。

## 2. 通用数据模型

| 层级 | 作用 | 关键字段 |
|---|---|---|
| 业务配置 | 支持剧情、电商、社媒、产品、企业和自由创作 | `business_profile`、质量策略、时长策略 |
| 场景世界 | 描述可复用的物理空间 | 场景标识、空间锚点、光线、时间 |
| 场景访问 | 描述一次进入或返回场景 | 访问顺序、连续性来源、时间状态 |
| 编辑镜头 | 最小叙事和剪辑单位 | 景别、机位、运镜、动作、人物、轴线 |
| 连续性段 | 约束相邻镜头的视觉一致性 | 人物、场景、道具、轴线、视线 |
| 生成单元 | 实际提交给视频模型的单位 | 单镜头/一镜到底、起止帧、时长、提示词 |

## 3. 人物与场景覆盖矩阵

| 人物模式 | 单场景 | 多场景 | 主要约束 |
|---|---|---|---|
| 无人物 | 支持 | 支持 | 空间结构、光线、产品/物体位置 |
| 单人 | 支持 | 支持 | 角色身份、服装、发型、位置、动作承接 |
| 双人 | 支持 | 支持 | 角色身份、左右关系、180 度轴线、视线匹配 |
| 多人物/群像 | 支持 | 支持 | 主次人物、站位、遮挡、发言归属、调度路径 |

## 4. 执行和费用门禁

```text
剧本/分镜
  → 通用领域协议
  → 连续性与复杂度分析
  → 默认逐镜生成计划
  → 模型能力与价格校验
  → 用户确认镜头范围和人民币成本上限
  → 创建付费任务（零自动重试）
  → 逐镜质检、人工决定是否修复
  → 剪辑合成
```

以下情况会阻止付费提交：

- 未确认当前预检指纹；
- 未确认成本指纹或成本上限；
- 模型价格未知；
- 高复杂度方案未确认；
- V3 付费功能开关关闭；
- 请求内容与预检后发生变化。

## 5. 性能与隔离

- 剧情广告脚本只在进入剧情广告页签后加载，避免拖慢数字人和其他平台功能。
- 任务列表只返回轻量摘要，不读取每个任务的完整输出。
- 分镜列表分页渲染，默认每页 20 条，避免大项目一次创建大量 DOM。
- 通用生成内核为独立目录，剧情广告通过兼容层接入，不把业务逻辑继续堆入旧页面和旧服务。
- 旧任务数据继续可读；V3 只改变新执行计划，不破坏历史成品查看。

## 6. 功能开关与回滚

- `NEW_STORY_AD_V3_ENABLED`：控制 V3 规划能力。
- `NEW_STORY_AD_V3_PAID_VIDEO_ENABLED`：控制 V3 付费视频提交。
- 关闭付费开关时，历史任务、分镜和成品仍可查看，只阻止新的付费请求。
- 发布前保留服务器备份；如出现严重问题，可回滚代码并重启服务，不修改既有任务数据。

## 7. 验收标准

- 无人物、单人、双人、多人 × 单场景、多场景组合全部通过自动化测试。
- 默认逐镜生成，只有显式一镜到底才允许合并。
- 付费请求不存在隐式重试、隐式模型回退和未知价格提交。
- API、后台任务和浏览器端用户可见错误均为中文。
- 剧情广告未激活时不加载其大体积脚本。
- 旧任务仍能打开和查看，新旧数据结构可兼容。
- 相关自动化测试、接口测试和浏览器验收全部通过后才允许部署。
