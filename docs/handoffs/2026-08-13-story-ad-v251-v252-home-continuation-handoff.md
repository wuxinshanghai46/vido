## 4. 修改前后的关键数据流

### 4.1 期望数据流

```text
基础信息（任务名称、内容类型、用户目标）
  → 高级配置（是否使用参考材料）
  → 参考材料仅作为证据，不覆盖用户权威目标
  → 统一规划（人物/动物/商品/场景）
  → 稳定主体与场景身份
  → 逐项资产生成和确认
  → 正式剧情
  → 分镜/镜头/声音
  → 合成与最终成片
```

### 4.2 当前实际失败数据流

```text
用户目标 + 可选参考材料
  → 参考投影或模型重规划可能覆盖目标/场景
  → 人物、动物、商品、场景 ID 在重规划后改变
  → 页面仍携带旧 ID，或已有资产不能复用
  → 保存正式剧情又改变修订号/计划资格
  → AI 输出使用正常简称却被精确名称门禁误杀
  → 场景派生图供应商下载超时或计费未知
  → 无法稳定进入分镜与成片
```

### 4.3 已做的局部修复

- 用户内容类型和目标保持权威，参考材料只辅助理解，不能静默切换广告/剧情。
- “是否使用参考材料”归入高级配置；选择“否”时参考视频和商品/服务主体入口隐藏，选择“是”才显示。
- 参考分析候选超时、无效结构和资产规划失败时可以切换备用候选。
- 批量资产请求提交完整缺失主体集合；重规划后使用当前主体 ID。
- 人物服装被审核拒绝时可复用已审计素材进行本地安全裁剪。
- 场景生成请求使用包含目标身份的幂等键，避免不同场景串成同一任务。
- V251 修复保存正式剧情后 Active Plan 被错误判失效的循环。
- V252 放宽广告主体质量门禁：允许有上下文证据的正常简称，不再只接受完整名称逐字出现。

这些修复证明了若干局部根因，但没有解决跨步骤的稳定身份、修订依赖和供应商媒体恢复，所以不能据此宣称整体功能已修复。

## 6. “13 个资产但只有 4 个角色”的解释

页面侧栏出现的“13”是生成资产文件/视图数量，不是 13 个角色。该次剧情样例的业务主体是 3 个：周宁、陈默、橘猫；每个主体有多张档案视图/派生图，再加档案或占位数据，形成 13 个生成单元。页面筛选显示的“全部 4 / 人物 4”属于另一时点方案中的主体卡片计数，与生成文件数使用了不同统计口径。

这个设计容易误导，后续应分开显示：

- `主体：人物 2、动物 1、商品 0`
- `资产文件：已完成 13 / 总计 13`
- `场景：已规划 N、已生成 M`

不要再用一个“资产”数字同时表达角色数量和图片数量。

## 7. 回家后优先修复方案

### P0：先做任务状态审计器，停止盲目模型重跑

新增只读审计，单次输出以下权威数据：任务内容类型、用户目标来源、当前 Active Plan、人物/动物/商品/场景 profile ID、语义身份、修订号、已有资产、生成任务、发布清单、未知计费单元。先让错误状态可见，再继续修改。

验收标准：对上述广告与剧情任务运行审计时，能明确指出哪个步骤首次产生覆盖、ID 变化、重复场景或计划失效；审计本身不调用模型、不写数据。

### P0：稳定主体与场景身份

不要再把模型每次返回的名字或临时 ID 直接当长期主键。为人物、动物、商品和场景建立稳定 `semantic_key`；重规划使用 reconciliation 合并：

1. 同语义主体保留稳定 ID。
2. 同语义场景不得重复创建。
3. 已生成且规格兼容的资产映射到新计划，不重复付费。
4. 页面提交前只从最新权威计划读取当前 ID。
5. 回归必须覆盖名称缩写、名称变化、最大长度、连续重规划和并发提交。

### P0：明确修订依赖图

把全局修订号拆成依赖节点：`source → plan → assets/scenes → script → storyboard → voice → compose`。上游变化只失效真实依赖的下游；保存剧情不能反向让已确认的人物/场景计划失效。Active Plan 资格应由上游指纹和契约版本决定，而不是一个全局 revision 数字。

### P1：修复供应商媒体交付

对外部参考 URL 记录匿名访问、首字节延迟、Content-Type、Range 支持和完整下载时间。优先使用供应商文件上传/`file_id` 或稳定对象存储，不再让供应商下载响应慢的应用代理 URL。未知计费单元必须保持人工授权，未确认前不得自动重提。

### P1：建立真实 UI 固定样例

建立广告和剧情各一套确定性界面夹具，覆盖：

- 新建、内容类型、参考材料“是/否”显隐。
- 用户目标读回不被覆盖。
- 方案主体/场景数量与名称。
- 刷新、退出重进、跨步骤返回后的状态一致性。
- 人物/动物/商品/场景资产生成与失败恢复。
- 剧情、分镜、镜头、声音、合成、最终视频播放。
- 所有中文提示无乱码，错误提示放在对应操作区域。

真实生产冒烟只能在确定性门禁通过后进行，且一次只验证一个原失败点，避免大范围重复付费。

### P1：修复发布门禁

将“家庭电脑仅定向测试”改成明确配置，不依赖主机名猜测。发布器要实时输出当前阶段、已耗时和下一步；发布开始前检查活动任务，发布后再核对制品哈希、PM2、内外网健康和 SQLite。
