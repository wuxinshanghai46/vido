## 二、本轮真正解决的问题

### 2.1 修改后仍调用旧内容

此前存在多个独立缺口：

- 点击生成时不一定等待自动保存完成；
- 保存期间再次编辑可能丢失变更范围；
- 后端相信客户端提交的 `change_scope=none`；
- 浏览器会把旧剧本、分镜、场景、关键帧和视频快照重新写回；
- 客户端收到“服务器已删除旧产物”时仍可能保留本地旧值；
- 后台任务完成时没有统一确认自己是否仍属于当前输入版本。

本轮统一改为：

```text
用户编辑
→ 客户端编辑序号
→ 服务器保存确认
→ 内容版本递增
→ 依赖产物失效
→ 封存不可变输入快照
→ 后台任务携带版本、快照、输入指纹
→ 完成时再次核对版本
→ 只发布属于当前版本的产物
```

现在旧版本任务即使晚返回，也不能覆盖当前剧本、分镜或媒体产物。

### 2.2 用户具体想怎么演

场景配置阶段新增“剧情与表演要求”，用户可以填写：

- 剧情走向；
- 人物动作；
- 表情变化；
- 台词或旁白；
- 节奏与转折；
- 结尾方式；
- 必须出现或禁止出现的内容。

第一步仍负责“做什么广告、商品是什么、需要哪些人物和场景”；新增字段负责“人物怎么演、剧情怎么推进”。两者不会直接拼成一段混乱提示词，而是先编译为结构化创意合同。

创意要求不能覆盖：

- 已确认人物身份；
- 已确认商品事实；
- 已锁定场景和稳定场景 ID；
- 用户明确的镜头数量与顺序；
- 禁止新增人物、场景或道具等约束。

发生冲突时会在调用模型前提示，不会带着冲突继续付费生成。

### 2.3 一次生成完成

点击“生成剧本”现在进入 `script-package` 文本包阶段：

```text
生成前保存屏障
→ 输入冲突检查
→ 内容快照
→ 剧本生成与质量检查
→ 可恢复错误的内部有限修复
→ 分镜生成与连续性检查
→ 原子发布当前版本剧本和分镜
```

结构化文本质量失败最多在系统内部执行两次有界修复，不再要求用户反复点击或依赖研发人员临时改代码。

仍保留必要的人机确认边界：

- 用户确认人物、商品和场景资产；
- 用户审核剧本与分镜；
- 图片和视频付费阶段继续执行预检与确认；
- 供应商鉴权、余额、审核拒绝或持续不可用不会无限自动重试。

### 2.4 人物和场景一致性

- 创意动作中的人物必须能解析到已确认人物；
- 无人广告不能要求人物出镜或说台词；
- 新场景、新人物或新道具不能在剧情阶段静默创建；
- 场景资产、分镜、关键帧和视频均受内容版本与资产 ID 约束；
- 剧本修改会让旧分镜和相关下游产物失效；
- 分镜局部修改会保留仍兼容的关键帧合同，但修改镜头会标记为过期；
- “一面墙”仍按主平面数量 1 处理，不会自动解释为“无缝连续墙面”。

### 2.5 2026-07-27 晚间追加：场景已通过却提示未保存配置

线上双场景卡片均显示完整空间锁，但点击生成剧本曾返回 `SCENE_CONFIG_REQUIRED`。根因不是图片或 QA 未通过，而是活动场景标签被序列化到兼容顶层 `scene_spec`，普通保存因此被后端误判为整个场景域发生变化，删除了当前版本的 `scene_config` 和 `scene_assets`；任务视图又从历史 context/checkpoint 补回两张卡片，形成“页面显示通过、当前合同缺失”的状态分叉。

现在统一为：

```text
活动标签切换
→ 只改变页面选择，不形成业务修改或自动保存

完整 scene_plan
→ 当前场景计划唯一权威
→ 后端以已持久化 scene_config 比较真实变化
→ 真实修改必须提交完整计划
→ 稳定 ID 且规格未变的资产可保留
→ 已失效 context/checkpoint 不得冒充当前资产
```

生产目标任务已用历史已发布 lineage 做零模型恢复：

- 当前内容版本：2；
- 状态：`working / scene_config_done`；
- 当前场景：城市公园草坪、现代家庭空间；
- 两个场景均为 V7、schema 6、5 个视图、完整空间锁；
- 模型调用计数修复前后均为 116，增量 0；
- 当时场景门禁已经恢复；随后发现下游结构修复模型路由和重复初稿调用的新阻塞，该“可以测试”结论已撤回，最终状态以 2.6 为准。

### 2.6 2026-07-27 夜间追加：进度迟到、结构修复失败与品牌 Logo 配置

生产证据确认主剧本模型已成功返回，但返回镜头数不等于用户明确的 9 镜，随后进入 `blueprint_structure_repair`。该阶段没有继承主剧本路由，误用全局故事模型池，并把默认最多 3 次尝试显示为“3/31 预算耗尽”；失败重试时又重新生成整份初稿，导致模型调用从 116 增至 124。

现在统一为：

```text
点击生成
→ 立即显示保存/预检进度
→ 单次完整草稿确认
→ 主剧本生成
→ 按内容版本 + 输入指纹保存可恢复初稿
→ 结构修复继承主剧本模型路由
→ 失败时保留同版本初稿
→ 内部恢复或用户重试只继续修复，不重新购买初稿
→ 成功后删除检查点
```

错误信息现在分别显示“本阶段实际尝试候选数”和“全部可用候选数”，不再把候选池数量解释为费用、余额或可用次数。

品牌 Logo 同时完成真实生产闭环：

- 场景配置页新增专用 Logo 图片上传；
- 用户必须确认拥有使用及发布授权；
- 可设置位置、画面宽度占比和结尾展示时长；
- Logo 不进入图片或视频模型提示词；
- 最终成片由本地 FFmpeg 原样叠加；
- 未确认授权或素材不可用时，合成前明确阻断。

### 2.7 2026-07-27 流程顺序追加：锁定资产后再设置剧情

场景配置页此前把“视频基础信息”“剧情与表演要求”和 Logo 放在资产生成结果之前，顶部又始终显示“生成剧本”，导致用户尚未完成并核对人物、主体和完整场景形象时就能填写下游剧情，甚至直接启动剧本生成。“生产模式”虽然进入提示词，却被误归类为来源变更，并未像页面文案所说控制 QA 策略。

现在流程收敛为：

```text
广告需求
→ 生成人物 / 主体 / 完整场景形象
→ 所有必需资产通过并锁定
→ 点击“下一步：设置剧情与表演”
→ 选择“剧情呈现方式”
→ AI 辅写或手写“剧情与表演要求”
→ 可选配置已授权 Logo 后期落版
→ 确认剧情设置并生成剧本
```

关键门禁：

- 必需人物、宠物和每个场景未齐全或未锁定时，不能进入剧情设置；
- 来源、人物、商品或场景变更后，原剧情设置确认自动失效，必须重新核对；
- UI 发起 `blueprint`、`storyboard` 或 `script_package` 时，后端再次检查 `story_setup_confirmed`，不能绕过前端直接生成；
- “剧情呈现方式”只控制剧本叙事与表演策略，不再宣称控制 QA；
- “AI 辅写剧情与表演”使用独立结构化合同，只允许在已确认人物、商品和场景范围内补写剧情，不得新增人物、场景、道具或商品事实；
- Logo 仍为可选后期素材，不交给图片或视频模型生成。

2026-07-28 UI 层级微调：唯一的“下一步：编写剧情与表演”主按钮已移动到“基础信息 / 场景配置”标题栏右上角；场景资产结果下方只保留就绪状态摘要。按钮仍使用同一资产就绪判断，未完成时禁用，进入剧情设置后隐藏，服务端 `story_setup_confirmed` 门禁没有放宽。资产就绪后，权威 `button-state.js` 会为按钮设置与其它“下一步”主操作一致的 `is-next` 状态，统一渐变背景、文字颜色、悬停位移和阴影；禁用或忙碌时不会显示可点击指向。该权威模块已纳入发布清单，避免只更新旧 UI 备用路径。

## 六、建议测试顺序

### 测试 1：最新编辑是否生效

1. 打开已有剧情广告任务。
2. 修改第一步广告想法。
3. 不等待自动保存提示，立即点击生成。
4. 检查新剧本是否使用刚输入的内容。
5. 确认旧剧本和旧分镜没有重新出现。

预期：系统会先完成保存确认，再启动新版本生成。

### 测试 2：剧情与表演要求

在新字段中输入类似：

```text
林晓从画面左侧缓步进入，开始略显疲惫；使用商品后表情逐渐放松，
恢复专注并完成工作，最后看向镜头说出品牌口号。
禁止新增人物，禁止切换到其他场景。
```

检查：

- 人物是否仍是已确认人物；
- 动作、表情和台词是否进入剧本；
- 是否没有擅自新增场景、人物或道具；
- 剧本与分镜是否形成同一条剧情。

### 测试 3：冲突是否在生成前阻断

无人广告中填写“女主角面对镜头说台词”。

预期：系统提示输入冲突，不调用模型。

### 测试 4：剧本修改后的下游失效

1. 生成并保存剧本、分镜。
2. 修改剧情结尾或关键动作。
3. 再次生成。

预期：旧分镜和受影响下游产物失效，新生成只能读取当前内容版本。

### 测试 5：结构修复失败后的恢复

若出现供应商临时失败，保留支持编号并等待后重试一次。

预期：错误显示本阶段真实尝试数；同内容版本复用已生成初稿，不再次调用主剧本模型。不要连续重复点击。

### 测试 6：品牌 Logo 后期落版

1. 在场景配置页上传 PNG、JPG 或 WebP Logo。
2. 勾选素材授权确认。
3. 设置位置、宽度和结尾展示时长。
4. 完成成片合成。

预期：图片/视频模型不生成 Logo；最终视频按配置叠加上传素材。未勾选授权时合成明确阻断。

### 测试 7：单主墙

输入“一面艺术展示墙”，但不写“无缝”。

预期：

- 主材质平面数量为 1；
- 不自动变成无缝连续墙面；
- 不新增侧墙、立柱、壁龛或重复展示墙；
