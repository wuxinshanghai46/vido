# VIDO 与 Liblib 案例人物真人感差距分析及优化交接

> 日期：2026-08-03  
> 目标分支：`codex/story-ad-v3-upgrade`  
> 竞品案例：[Liblib「虫村第二集」](https://www.liblib.tv/detail/7620db473ccb4a52978fcd02a43321bd)  
> 文档性质：只读分析与实施方案；本轮没有修改生成代码、调用付费模型或覆盖已有任务资产。

## 1. 结论先行

VIDO 当前人物与竞品的差距不是单一的“模型不够好”，也不只是“视频只有 720p”。核心是整条质量链的上限被多处同时压低：

1. **人物母版的有效像素不足**：VIDO 先让模型生成多宫格图集，再把每格本地裁切并放大。身份图集默认 1024×1024、2×2，每张脸在裁切前理论上最多约 512×512；输出文件即使标成 1024×1024，也不能恢复生成时不存在的毛孔、睫毛和发丝细节。
2. **逐镜头只带有限引用**：关键帧最多选择 4 张参考图，并且单个人物通常只取一张正脸或正面全身图。场景、多人、产品、道具会继续占用名额，动作、手部、侧脸等参考容易被挤掉。
3. **“真人感”只写在提示词里，未成为硬门禁**：代码已经要求毛孔、皮肤色差、绒毛、发丝和禁止塑料皮，但人物 QA 主要检查身份、年龄、服装、体型和手的归属；视频 QA 主要检查人物/产品/场景/动作/数量/水印/时序证据。清晰但假、身份一致但蜡像化、脸部轻微抖动的视频仍可能通过。
4. **默认交付链继续损失细节**：视频默认 720p，统一缩放裁切到 1280×720、720×1280 或 1680×720，再强制 30fps、H.264 `veryfast`、CRF 22 重编码。头发、皮肤、眼睛等高频细节最容易在二次编码中受损。
5. **缺少人物视频精修与母版流程**：现有最终 QA 能验证可解码、时长、音频、黑帧和长冻结，但没有视频级超分、时序去闪、身份锁定的人脸修复、局部细节恢复、统一调色和高质量母版编码门禁。
6. **竞品采用“逐节点生产 + 多候选筛选”**：页面可见大量独立人物图、人物设定板、场景图、风格/影片参考、关键帧、视频节点及分支候选。其真人感来自高质量源图、适合模型的镜头设计、逐镜头摄影约束和人工筛选的叠加，而不是一次生成整个项目。

因此，**只把 VIDO 的 `video_resolution` 改成 1080p 不会根治问题**。正确顺序是：先重建人物母版和逐镜头参考包，再增加真人感 QA，随后升级视频生成、时序精修和母版编码。

## 2. 证据等级

### 2.1 已确认的竞品页面事实

浏览器只读检查了案例详情、播放器、创作过程和故事板：

- 案例标记为 AI 生成，页面视频时长约 12 分 21 秒。
- 创作过程不是单一路径，可见大量互相连接的独立图片和视频节点。
- 人物素材包含近景正脸、三分之二侧脸、全身正背面、手部/饰品细节以及不同服装状态，不只是一张人物档案总图。
- 工作流同时使用独立场景图、色调/美术参考和影片画面参考；可见多个相似节点与视频候选，说明存在迭代和挑选。
- 故事板中可见 2048×2048、2016×864、2048×1152 等图片资产；视频节点可见约 1470×630、6 秒/8 秒/15 秒等短片段。
- 逐镜头描述包含人物和场景锚点、镜头焦段、光圈、快门、ISO、景深、运镜、表演细节、声音和转场，并明确限制塑料皮、过度磨皮、CG 感等问题。

这些事实说明：竞品展示的是一套重制作工作流，而不是“单张角色图 + 一段通用提示词 + 一次视频调用”。

### 2.2 已确认的 VIDO 代码事实

| 环节 | 当前实现 | 直接影响 |
|---|---|---|
| 人物档案 | `personDossierCompiler.js` 用 4 次供应商调用生成 body / identity / expression / action 四张多宫格，再本地拆成 20 个原子资产 | 每个格子的生成原生像素只占图集一部分，本地放大不能产生真实细节 |
| 身份图 | 1024×1024 的 2×2 图集，本地拆分为四张 1024×1024 | 每格原生上限约 512×512，后续是放大，不是真 1K 人脸 |
| 全身图 | 2×2 图集，每格再输出 768×1024 | 人物在格内占比更小，脸和手的有效像素进一步下降 |
| 表情/动作 | 3×2 图集一次生成 6 个状态 | 单格宽度最多只占图集三分之一，动作越全身化，脸和手越小 |
| 关键帧引用 | `referenceSelectionService.js` 最终 `.slice(0, 4)`；单成员优先只取正脸或正面全身 | 多视角身份、手部、动作、服饰细节不能稳定同时进入同一镜头 |
| 图片规格 | `resolution: '2K'` 是业务标签，实际请求规格由 `sizeFor()` 决定；默认正方形 1024×1024、横图 1536×1024 | 代码不能仅凭“2K”字段证明供应商真正生成了 2K 细节 |
| 人物关键帧 QA | 检查身份、年龄、服装、体型、手归属；常规身份阈值 0.82 | 没有脸部锐度、皮肤微纹理、发丝、塑料皮、光学真实度评分 |
| 视频逐帧 QA | 抽取代表帧，检查身份、产品、场景、动作、人数、宠物、水印和时序证据 | 没有面部 landmark 抖动、局部变形、闪烁、皮肤纹理和压缩损伤硬门禁 |
| 成片技术 QA | 检查解码、时长、音频、黑帧、长冻结和转场边界 | 技术可播放不等于真人感或商业母版质量 |
| 默认视频规格 | `contextBuilder.js` 默认 `720p` | 人脸在中远景里可用像素不足 |
| 标准化编码 | `videoAdapter.js` 强制缩放/裁切、30fps、H.264 `veryfast`、CRF 22 | 对细发、眼睛、皮肤等高频纹理产生额外损失，也可能改变原始运动节奏 |
| 后期 | 未发现专门的人脸时序稳定、视频超分、去闪、受控细节恢复和母版调色阶段 | 生成模型的小缺陷直接进入成片 |

### 2.3 目前只能作为推断的内容

- 无法仅凭页面确认竞品具体使用了哪个人物/视频模型、LoRA、FaceID、训练权重或精修软件。
- 无法证明页面展示的每个候选都进入最终成片，也无法确认其内部淘汰率和真实成本。
- 不能把竞品观感全部归因于 2K 图片或某个模型；1470×630 与 1280×720 的总像素接近，观感差异主要还来自脸部占画面比例、输入源质量、照明、镜头复杂度、候选筛选和后期。
- 供应商的“托管参考资产”相对严格首帧图生视频会损失多少身份或构图，只能通过同镜头 A/B 实测后确定。

## 3. “高清真人感”实际由六个维度组成

1. **空间清晰度**：原始人物母版是否真的含有足够像素，而不是把小格放大。
2. **身份特异性**：骨相、年龄、眼型、鼻唇、发际线、脸部不对称是否稳定，不是通用“网红脸”。
3. **光学真实度**：皮肤纹理、细发、眼睛湿润感、自然高光、真实景深和镜头像差是否可信。
4. **时序稳定性**：说话、转头、喝水、拿产品时，五官、牙齿、手指、杯口接触和饰品是否连续。
5. **摄影设计**：人物占画面比例、光线、背景复杂度、动作难度和镜头时长是否在模型擅长范围内。
6. **编码与后期**：是否保留原始帧率与细节，是否去闪、稳脸、调色并用母版级参数导出。

VIDO 目前在“身份/服装一致性”和“动作是否完成”上投入较多，但在第 1、3、4、6 项缺少硬门禁，因此容易得到“内容正确，但一眼像 AI”的视频。

## 4. 为什么用户截图中的竞品人物更像真人

- 人脸在画面中占比较大，模型有更多像素表达眼睛、嘴唇、皮肤和发丝。
- 侧窗自然光、柔和背景和浅景深降低了场景复杂度，人物与背景更容易融合。
- 喝饮品虽然涉及手和嘴，但动作幅度小、机位稳定、镜头时间短，属于视频模型更容易完成的动作。
- 人物设定板有正脸、侧脸、全身、背面和局部手部，逐镜头可以选与目标姿态最接近的参考。
- 工作流为同一目标保留多个节点和候选，失败结果不会直接成为最终成片。
- 摄影参数、表演微动作和负面限制逐镜头明确，而不是把人物、产品、场景、动作、转场全部挤进一个通用约束。

## 5. 建议的新质量链

### 5.1 A 段：人物母版不再以多宫格拆图作为生成真相源

保留现有 20 项档案结构和服装、鞋履、饰品细节，但改变生成方式：

1. 先生成或上传一张 **身份母版**：正脸近景，供应商最高原生规格，脸部占图高，禁止本地放大冒充高分辨率。
2. 再以身份母版分别生成三分之二侧脸、纯侧脸、全身正/背面、手部/腕表/饰品、镜头所需动作；每张都是独立供应商输出。
3. 多宫格只作为 UI 汇总展示图，不再从多宫格裁切得到权威原子资产。
4. 每类先生成 2–4 个候选，由自动 QA 和用户共同锁定；锁定后记录 `master_asset_id`、供应商原始宽高、是否发生过放大。
5. 原有服饰、鞋履、饰品优化不删除，全部挂到新的身份母版版本下；人物身份未变时，只让视觉下游失效，不重做剧本和场景。

建议新增硬规则：

- 正脸母版短边不得低于供应商原生 1536 或可用最高规格；脸部有效区域至少 700×700 像素。
- `upscaled=true` 的图不能成为身份母版。
- 手部、饰品、产品接触动作必须有独立高分辨率参考，不再依赖全身图里的小手。

### 5.2 B 段：建立“逐镜头参考包”，替换固定前四张策略

每个镜头生成一个可审计的 `ShotReferencePack`：

- 身份近景：与镜头角度最接近的一张。
- 姿态/全身：与动作起始姿态匹配的一张。
- 场景：当前机位的真实视角或关键帧母图。
- 产品/道具：仅在镜头需要时占位。
- 手部/饰品：特写或接触动作时提升到高优先级。
- 前一镜尾帧：需要动作承接或匹配剪辑时提升到高优先级。

如果供应商只允许 3–4 张参考，必须按镜头类型动态分配，不可继续使用统一静态顺序。UI 中展示“本镜头实际提交了哪几张图”，避免用户以为整个人物档案都会自动被模型看见。

### 5.3 C 段：关键帧先达到摄影级，再生成视频

1. 关键帧按最终画幅独立生成，电影宽银幕可用接近 2016×864，16:9 可用 2048×1152 或供应商最高原生档。
2. 人物中近景确保脸部有效区域足够；不要用远景验证皮肤真实度。
3. 每镜默认 2 个候选，高质量模式 4 个候选；低分候选自动淘汰，不直接进入视频。
4. 增加关键帧真人感硬门：
   - face sharpness / eye sharpness
   - skin microtexture / plastic-skin risk
   - hair strand detail
   - lighting integration / contact shadow
   - anatomy / hand contact
   - compression / oversharpen / halo
5. 用户可 200% 放大对比候选并锁定，锁定后才允许产生付费视频。

### 5.4 D 段：视频生成改成“短镜头、低复杂度、质量档”

- 提供“快速 720p”和“电影级 1080p”两档；电影级模式必须请求供应商原生 1080p 或最高可用规格，不能先 720p 再放大。
- 人物主镜头优先严格首帧图生视频；若供应商因合规只能使用托管人物资产，必须用同一关键帧做构图/身份回验。
- 每条人物视频建议 4–8 秒，一个镜头只完成一个主要动作；复杂动作拆成起始、接触、结果三个镜头。
- 电影模式默认 24fps 或保留供应商原生帧率；禁止无条件强转 30fps。只有明确交付要求时才做运动补偿式帧率转换。
- 同镜头至少保留 2 个视频候选；对身份、脸部稳定和动作接触综合评分后再选成片。

### 5.5 E 段：增加受控后期，不把“美颜”当“修复”

推荐顺序：

1. 时序去闪和局部变形检测。
2. 身份锁定的人脸稳定；只修复漂移，不改变骨相、年龄和皮肤质感。
3. 必要时做视频超分/细节恢复；若源视频没有真实细节，标记为增强而不是宣称原生高清。
4. 轻量去噪、锐化和统一调色；禁止磨皮、瓷娃娃脸和过度 HDR。
5. 输出高质量母版和网页交付版两份：母版建议 H.264/H.265 慢速预设、CRF 16–18；网页版可 CRF 20 左右。实际参数需用样片和带宽 A/B 决定。

### 5.6 F 段：最终 QA 从“能播放”升级为“能交付”

新增三层门禁：

- **技术层**：分辨率、帧率、码率、色彩空间、完整解码、音画时长、黑帧、冻结。
- **单帧视觉层**：脸/眼锐度、皮肤微纹理、塑料皮风险、发丝、手部、产品文字、曝光、压缩块和光晕。
- **时序层**：身份分数的均值与最低值、五官 landmark 漂移、闪烁、面部/手部形变、饰品跳变、接触动作连续性。

任何“身份一致但塑料皮”“首帧清楚但转头后脸糊”“动作正确但手指融合”的结果都应阻止进入最终成片。

## 6. 界面需要调整的功能

### 人物档案页

- 增加“身份母版候选”区域，支持 200% 放大、并排比较和“锁定身份母版”。
- 每张资产显示真实原始尺寸、供应商、是否裁切/放大、版本号。
- 原有服装、鞋履、饰品入口保留；新增“只重生此项”和明确的下游失效范围。

### 分镜/关键帧页

- 每镜新增“参考包”抽屉，展示实际传给模型的身份、动作、场景、产品/道具、连续性参考。
- 关键帧由单张改成 2–4 张候选对比；显示人物真实感、身份、手部、场景和产品分项分数。
- 未锁定关键帧时，视频生成按钮明确禁用并说明原因。

### 视频页

- 增加“快速 / 电影级”质量档、原生分辨率和预计成本提示。
- 同镜头视频候选支持悬停播放、同步对比和关键问题标记。
- 显示“原生生成规格”和“最终交付规格”，不得把后期放大标成原生 1080p。

### 成片页

- 增加母版 QA 面板：身份最低分、脸部锐度、时序抖动、闪烁、编码规格和失败镜头定位。
- 仅重做失败镜头与相邻转场，不重新调用已通过的人物、场景和视频。

## 8. 回归与验收标准

### 静态/单元回归

- 独立人物原子图不再带 `locally_split: true`，且记录供应商原始宽高。
- 任何本地放大资产不得成为 `identity_master`。
- 参考包超过供应商上限时，测试人物特写、产品手持、多人、宠物和无人物镜头的动态优先级。
- 720p/1080p、16:9/9:16/21:9、24/25/30fps 均测试实际 ffprobe 输出。
- 旧任务兼容读取，但新任务不能再次写入旧图集裁切真相源。

### 真实样片 A/B

选择同一人物、同一场景、同一 5 秒轻动作，至少对比：

1. 当前图集裁切 + 720p + CRF22。
2. 独立人物母版 + 当前视频链。
3. 独立母版 + 原生 1080p。
4. 独立母版 + 原生 1080p + 时序精修/母版编码。

每组不少于 2 个候选，盲评记录：身份一致、真人感、脸部细节、时序稳定、手部、场景融合和综合可用率。只有 A/B 能确定每个环节的真实收益和成本。

### 可测试声明门禁

实现后必须同时满足：定向测试、完整平台回归、语法检查、真实样片 A/B、生产部署后健康检查、生产任务只读核对、无已知重复付费或旧资产续用风险，才可让用户正式验收。

## 9. 建议实施顺序与成本控制

1. **第一阶段（收益最大）**：人物独立母版、原生尺寸审计、逐镜头参考包、真人感 QA。先不改视频供应商，验证输入和门禁能提高多少。
2. **第二阶段**：电影级 1080p、保留原生帧率、视频多候选和高质量编码。
3. **第三阶段**：时序稳脸、去闪、受控超分和统一调色。
4. **第四阶段**：根据 A/B 结果再决定是否引入新的身份适配模型或训练方案；涉及真人训练必须有明确授权、删除机制和隐私审计。

成本必须做成质量档：普通任务继续可选快速模式；只有用户选择电影级或 QA 判定关键镜头时才增加候选和后期。失败只重做失败镜头，禁止整项目重跑。

## 10. 旧代码与缓存迁移要求

- 新旧人物资产结构必须有明确 `schema_version` 和 `build_id`，新任务只允许写新结构。
- 旧图集裁切逻辑迁移完成后停止加载，不得让旧前端或缓存继续调用。
- 静态资源 URL 必须带统一 build 版本；生产只保留当前构建，旧入口重定向或返回 410。
- 读取旧任务时只做兼容投影，禁止静默把旧裁切图升级成新身份母版。
- 发布清单必须覆盖人物编译、参考选择、QA、视频编码和前端资源；逐文件 SHA-256 核对后才能宣布更新生效。
