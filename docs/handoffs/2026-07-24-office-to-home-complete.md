## 四、今天完成的功能

### 4.1 目标时长不再被固定为十五秒

- 目标时长统一从用户明确需求、结构化输入和任务上下文中解析。
- 任务恢复、去重指纹、场景生成和付费执行前使用同一规范时长。
- 旧任务不能用默认三十秒覆盖用户明确写出的十五秒。
- 十五秒只是历史交接任务的测试样例，不是平台固定值。
- 新任务仍支持 10–120 秒，因此三十秒、六十秒均可以创建。
- 时长变更会进入任务指纹，避免不同时长任务被错误复用。

### 4.2 AI 帮写内容的换行和布局

- 修复模型返回字面量 `\n\n` 后直接显示在文本框的问题。
- 新任务 AI 帮写和旧任务恢复共用格式化边界。
- 解码字面量换行、清理 Markdown 标记并规范中文板块标题。
- 需求文本框增加可读排版样式。
- 生产截图对应旧任务 `d36055d2-...` 已使用真实浏览器确认：
  标题和段落正确分行，不再显示 `\n\n`。

### 4.3 人物去 AI 感和真实感

最终采用的规则不是大头照，而是原有正面全身参考。

- 人物资产保持正面、侧面、背面、自然动作四张全身参考。
- 不新增第五张大头照，不增加图片生成次数。
- 漫路 / Seedance 单人物素材仍优先使用正面全身静态图。
- 保留并加强以下真实感提示：
  - 毛孔、细小皮肤纹理和自然肤色层次；
  - 唇纹、碎发、真实眼部和手部细节；
  - 非模板化骨相和轻微左右不对称；
  - 剧情驱动的自然微表情；
  - 人物与环境光影、色温、阴影方向的融合；
  - 跨镜头脸、年龄感、发型、体态、服装和鞋的一致性；
  - 禁止塑料皮肤、蜡像脸、过度磨皮和通用 AI 模特脸。
- 关键帧提示词压缩器为人物真实感保留独立预算，避免真实感规则在
  供应商长度限制前被截断。

今天曾短暂实现“正面肩上大头首图”，随后根据负担和全身一致性问题撤回。
当前生产最终状态是“正面全身”，不要再按早期记录误以为大头照仍在使用。

### 4.5 人物 + 宠物混合主体

新增正式主体模式：

```text
human_pet = 人物 + 宠物
```

人物和宠物不再互斥：

- `expected_people`：精确人物数量。
- `expected_animals`：精确宠物 / 动物数量。
- `cast_profiles`：逐人物档案。
- `pet_profiles`：逐宠物档案。
- 人物数量和宠物数量分别进入分镜、关键帧合同、视频预检和逐帧 QA。
- 纯动物模式会清除旧人物素材，不能误带人物。
- 混合模式保留人物身份合同，同时建立宠物合同。
- 每镜允许明确人物或宠物数量为零，不能用全局数量覆盖镜头明确缺席。

宠物一致性锁包含：

- 物种和品种；
- 毛色、毛发质感和花纹；
- 面部标记和眼睛；
- 体型、年龄感、耳朵和尾巴；
- 项圈和配饰；
- 禁止跨镜头增删、替换、变色、复制或合并宠物。

视频逐帧 QA 已增加：

```text
animal_count_pass
pet_identity_pass
```

### 4.6 双人、多人和宠物的独立资产

旧根因：

- `expected_people` 只是数量元数据。
- 人物生成接口始终只创建一套主要人物四视图。
- 其他人物没有独立身份资产和合同。
- 宠物只有文字描述，没有参考图资产。
- 多人视频可能把第一位人物上传成整组人物。

当前实现：

- 每位人物分别生成一套 2×2 四视图身份表：
  - 正面全身；
  - 侧面全身；
  - 背面全身；
  - 自然动作全身。
- 每只宠物分别生成一套 2×2 四视图身份表。
- 每个主体都有稳定 ID、成员序号、角色、参考图和独立视觉合同。
- 全部必需成员通过验证后，聚合人物 / 宠物合同才是 `verified`。
- 三个人加一只宠物对应四次主体图片模型提交。
- 页面在提交前显示实际图片模型提交数。
- 多人视频不再把第一位演员的 `asset://` 当成整组人物。
- 供应商只支持单人物素材时，使用已审核关键帧作为视频首帧身份锁。

### 4.7 全主体参考板与供应商四图上限

发布后复核发现：

- 关键帧供应商最多接收四张参考图。
- 三个人、一只宠物再加场景时，原顺序会截断最后一个主体。

最终修复：

- 两个及以上主体在本地合成一张全主体身份参考板。
- 参考板采用平衡网格，不触发模型，不产生额外模型费用。
- 参考板写入任务主体合同和检查点，恢复时复用，不重复生成文件。
- 关键帧四张参考图按以下优先级保留：
  1. 当前场景；
  2. 全主体身份参考板；
  3. 产品；
  4. 上一镜连续性。
- 提示词明确参考板只是身份图谱：
  - 只生成当前镜头声明的人物和宠物；
  - 不复制参考板网格或影棚背景；
  - 不因为主体出现在参考板就强制让其出镜。

### 4.8 取消、断点恢复和重复费用保护

- 每完成一个人物或宠物资产就写入任务级检查点。
- 用户取消后，在当前模型调用边界停止，不提交后续主体。
- 恢复只生成缺失成员，不重复生成已完成成员。
- 检查点指纹包含：
  - 任务 ID；
  - 需求；
  - 人物设定；
  - 精确人物 / 宠物数量；
  - 逐人物档案；
  - 逐宠物档案；
  - 图片模型；
  - 描述。
- 修改宠物毛色或人物外观后不会误复用旧检查点。
- 相同主体批次并发提交时，服务端拒绝第二个请求，避免双击重复付费。

取消能力边界必须继续如实说明：

- 还没有提交给供应商的后续调用可以完整阻止。
- 已被供应商接收的单次远端异步请求没有供应商撤销接口。
- 平台会停止轮询、停止后续调用并丢弃迟到结果。
- 不能承诺供应商立即停止计算，也不能承诺该次请求一定不计费。

### 4.9 多场景空间资产和一致性

场景配置现在会先输出独立物理空间清单：

```json
{
  "scene_mode": "single/multi",
  "spaces": [
    {
      "id": "稳定空间 ID",
      "name": "中文空间名",
      "description": "布局和识别特征",
      "story_purpose": "剧情作用"
    }
  ]
}
```

- 家庭、办公室、门店和户外等不同地点必须拆成独立空间。
- “按剧情自动判断”识别到多个空间后，页面自动切换多场景锁定。
- 页面显示需要生成的独立场景资产数量。
- 系统不会未经确认自动批量生成所有空间，避免扩大图片调用。
- 用户需要：
  1. 生成当前场景；
  2. 修改为下一个独立空间；
  3. 点击“追加新场景”；
  4. 直到资产数量等于空间清单数量。
- 每套场景资产分别保存：
  - 主视图；
  - 反向视图；
  - 互动视图；
  - 细节视图；
  - 俯视布局；
  - 材质、光线和表面拓扑；
  - 关键物件、区域和机位；
  - 场景版本与视觉 QA。
- 少于自动识别的空间数量，或者任一场景未验证，都会阻止生成分镜。
- 每镜必须绑定已有 `scene_id`。
- 切换空间必须填写与当前剧情相关的转场理由。
- 不允许把一套空间资产静默复用为另一个独立地点。

## 十、已知限制与继续优化方向

### 10.1 必须通过真实新任务验证的部分

代码、接口、状态、门禁和回归已经闭环，但以下效果必须由真实付费生成证明：

- 三个不同人物的脸和体态是否足够区分；
- 宠物在关键帧和视频中是否稳定；
- 全主体参考板对四图上限的实际供应商效果；
- 多空间切换后的材质、光线和空间拓扑；
- 三十秒或六十秒成片的跨镜连续性；
- 人物真实度是否达到竞品效果；
- 最终动作、节奏、表情和商品展示效果。

在真实新任务完成前，只能说“功能和接口具备生成条件”，不能把竞品级最终效果
当成已经通过成片验收。

### 10.2 多场景仍需要用户确认成本

- 自动判断只识别空间数量并执行门禁。
- 不会自动连续生成所有空间。
- 每个空间仍需用户分别确认并点击生成 / 追加。
- 这是费用安全设计，不是漏做。

### 10.3 漫路人物素材边界

- 单人物可使用既有正面全身静态图创建 / 复用 `asset://`。
- 多人物不能把第一位人物素材当成整组人物。
- 多人物视频优先使用已审核关键帧首帧锁。
- 不建议为大头照额外生成第五张图或额外上传一份素材。

### 10.4 本地 Video Canvas Worker 警告

本地启动主服务时，Video Canvas Worker 可能提示本地 V2 数据表未迁移并退出。

- 剧情广告主服务仍可在 3007 健康运行。
- 该警告没有影响今天的剧情广告 V2.0 回归。
- 不要仅为了消除警告就直接执行强制数据库迁移。
- 如下一步要开发 Video Canvas，应先单独审查迁移内容、备份和回滚方案。
