# 剧情广告精细化工作台方案

> 日期：2026-07-31
> 目标：在不复制竞品复杂度、不堆叠重复代码的前提下，把“参考 → 资产 → 剧情 → 镜头 → 成片”做成可追溯、可局部重做、不会串任务的精细化生产系统。

## 一、结论

精细化不等于增加更多步骤、更多提示或把 100 多个技术节点直接展示给普通用户。

VIDO 应采用“两层结构”：

- 用户层：4 个长期存在的工作区，用户可以自由往返，不用理解底层节点。
- 系统层：人物、产品、空间、剧情节拍、镜头、候选素材均是有稳定 ID、版本、来源指纹和依赖关系的节点。

四个工作区：

1. 参考与目标
2. 资产工作室
3. 故事与镜头
4. 生成与审核

底层图谱负责严谨性，界面只呈现当前决策和下一步动作。

## 二、这次线上事故对新架构的硬约束

### 1. 任务会话必须原子隔离

点击“新建剧情广告”时，在读取 URL、恢复草稿或执行自动保存之前，一次性完成：

- 终止旧任务轮询和迟到响应写回。
- 清空旧任务 ID、旧参考分析 ID、旧自动生成文案和旧资产引用。
- 创建新的会话 epoch。
- 只保留用户级偏好，例如默认画幅；不保留任务级内容。

### 2. 参考来源必须成为强绑定实体

每个参考来源至少保存：

- `analysis_id`
- 文件名
- 文件大小
- 时长、宽高、编码
- 分析状态
- 来源版本

新文件一旦被选中，旧分析立即失效。当前分析失败、取消或进行中时，绝不回退上一个已完成分析。

### 3. 事实与创作必须分层

- 事实层来自确定性证据：产品、品牌/型号、可见文字、真实空间、材质、时间点。
- 创作层由模型整理：剧情结构、节拍、人物方向、场景设计和镜头意图。
- 模型可以补充创作层，不能删除已经取得的事实证据。
- 当模型字段缺失时采用字段级证据兜底，不重新调用一次模型。

### 4. 未完成参考必须在付费调用前阻断

浏览器和服务端同时检查：

- `uploaded/importing/queued/running`：等待分析完成，或删除参考后继续。
- `failed/cancelled`：重新分析，或删除参考后继续。
- `completed + valid`：才允许把参考结果投影到资产和剧情。

服务端门禁是最终权威，确保绕过前端也不会触发下游付费。

## 三、界面会变成什么样

## 3.1 全局框架

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 剧情广告 · 项目名称                         已保存 10:32   任务中心 │
├──────────────┬───────────────────────────────────────────────────────┤
│ 参考与目标   │                                                       │
│ 资产工作室   │                  当前工作区                           │
│ 故事与镜头   │                                                       │
│ 生成与审核   │                                                       │
│              │                                                       │
│ 项目状态     │                                                       │
│ ● 参考已确认 │                                                       │
│ ● 资产 3/4   │                                                       │
│ ○ 镜头待确认 │                                                       │
└──────────────┴───────────────────────────────────────────────────────┘
```

变化：

- 顶部不再放六个一次性步骤卡片。
- 左侧工作区长期存在，用户可随时返回修改人物、产品或某个场景。
- “完成度”由底层依赖计算，不强迫用户按固定步数操作。
- 技术机位、模型名、节点连线默认隐藏在“来源与版本”抽屉中。

## 3.2 参考与目标

```text
┌─ 参考与目标 ─────────────────────────────────────────────────────────┐
│ 广告目标                                                             │
│ [用一句话说明产品、受众和希望观众采取的行动____________________]     │
│                                                                      │
│ 参考视频（可选）                                                     │
│ ┌──────────────────────────────────────────────────────────────────┐ │
│ │ ▶ 保时捷718.mp4   44.5 秒 · 2560×1440                 [删除]    │ │
│ │ 状态：等待分析                                      [开始分析]  │ │
│ └──────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│ 分析完成后显示：                                                     │
│ 主体：保时捷跑车 / 918 Spyder（来自 24.84–44.46 秒证据）             │
│ 环境：湿润山路、森林道路                                             │
│ 结构：车库建立悬念 → 山路驾驶 → 产品收束                             │
│                                                   [查看证据时间线]    │
│                                                        [确认并继续]  │
└──────────────────────────────────────────────────────────────────────┘
```

交互规则：

- 用户上传后只出现一个来源卡片和一个主要动作。
- 分析完成前不把半成品文案写进广告需求。
- 分析完成后先显示三项摘要：主体、环境、结构。
- 有冲突时只要求确认冲突字段，不让用户阅读整段内部提示词。
- “查看证据时间线”是可选详情，不影响普通用户继续。

## 3.3 资产工作室

```text
┌─ 资产工作室 ─────────────────────────────────────────────────────────┐
│ [人物 1] [产品 1] [场景 3] [道具 0]                                  │
│                                                                      │
│ 场景                                                               │
│ ┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐       │
│ │ S01 湿润山路     │ │ S02 山间隧道     │ │ S03 林间停车区   │       │
│ │ 主视图  ✓        │ │ 主视图  ✓        │ │ 待生成           │       │
│ │ 反打    ✓        │ │ 反打    待补     │ │                  │       │
│ │ 交互位  ✓        │ │ 交互位  ✓        │ │                  │       │
│ │ [查看] [重做]    │ │ [补缺失机位]     │ │ [生成场景]       │       │
│ └──────────────────┘ └──────────────────┘ └──────────────────┘       │
│                                                                      │
│ 右侧抽屉：布局 / 材质光线 / 互动区域 / 禁止项 / 来源版本             │
└──────────────────────────────────────────────────────────────────────┘
```

精细化单元：

- 人物：身份方向、脸部三视图、全身、服装、表情、动作。
- 产品：产品主档、多角度、细节、品牌/型号文字、不可变特征。
- 场景：每个独立物理空间单独建档，保存主视图、反打、交互位和细节位。
- 道具：只保存可独立移动且会参与剧情的物体；固定家具归场景。

每个卡片都包含稳定 ID 和版本，但普通用户只看到名称、缩略图、完整度和动作。

## 3.4 故事与镜头

```text
┌─ 故事与镜头 ─────────────────────────────────────────────────────────┐
│ 故事节拍： [建立悬念]──[出发]──[性能展示]──[情绪顶点]──[产品收束]   │
│                                                                      │
│ 镜头 04 · 3.0 秒                           使用 S01 / 产品 P01       │
│ ┌──────────────────┬───────────────────────────────────────────────┐ │
│ │ 关键帧 / 候选图  │ 画面：银色跑车沿湿润山路高速通过              │ │
│ │                  │ 动作：入弯，车身重心自然转移                  │ │
│ │                  │ 镜头：低机位侧向跟拍                          │ │
│ │                  │ 声音：轮胎过水声 + 音乐节奏抬升               │ │
│ │                  │ 连续性：沿用镜头 03 的车身方向和雨量          │ │
│ └──────────────────┴───────────────────────────────────────────────┘ │
│ [上一镜] [下一镜] [仅重做本镜] [展开高级参数]                        │
└──────────────────────────────────────────────────────────────────────┘
```

这里不展示竞品式大画布作为默认界面。大画布适合专业排错，不适合普通制作。

默认界面使用“节拍条 + 镜头卡”：

- 节拍负责故事结构。
- 镜头卡明确绑定人物、产品、空间、道具和上一镜依赖。
- 单镜重做只使本镜及明确依赖它的后续节点失效。
- 高级参数折叠后才显示机位、焦段、运动轨迹和种子。
- 可选“关系图”用于管理员或高级用户查看血缘，不承担日常编辑。

```text
┌─ 生成与审核 ─────────────────────────────────────────────────────────┐
│ 生成范围  [缺失镜头] [选中镜头] [全部镜头]                           │
│                                                                      │
│ 04  ✓ 画面通过  ✓ 连续性通过  ✓ 视频通过                            │

│ 06  — 等待镜头 05                                                   │
│                                                                      │
│ 费用预估：仅在真正付费前显示一次                    [确认生成 1 镜] │
│                                                                      │
│ 成片审核：时长 / 音画 / 字幕 / 品牌 / 连续性                         │
│                                                       [导出成片]     │
└──────────────────────────────────────────────────────────────────────┘
```

审核反馈必须落到具体资产或镜头，不能只给“生成失败”。

## 四、去掉哪些不必要提示

### 默认删除

- 页面顶部重复解释整个流程的长句。
- 每个区域重复出现的“系统将自动……”说明。
- `source_product_missing`、模型名、供应商错误、内部阶段名。
- 未展开高级设置时的机位、焦段、运镜术语说明。
- 同一状态同时出现在卡片、弹窗、Toast 和全局进度中的重复提示。
- 成功后没有下一步意义的 Toast。

### 默认保留

- 当前唯一阻塞原因。
- 当前唯一下一步动作。
- 会产生费用、覆盖用户修改、删除素材时的确认。
- 自动保存失败。
- 需要用户判断的证据冲突。

### 提示展示规则

同一事件只占一个位置：

- 行内状态负责持续状态。
- Toast 只负责短暂完成反馈。
- 弹窗只用于不可逆操作或费用授权。
- 技术详情只进入“详情”抽屉和日志。

错误文案采用“发生了什么 + 怎么继续”，例如：

> 未能确认当前视频的广告主体。请重新分析，或删除参考视频后按文字需求继续。

不再向普通用户显示：

> REFERENCE_VIDEO_ANALYSIS_SEMANTIC_INVALID: source_product_missing

## 五、底层数据模型

不照搬竞品 109 个可见节点，只实现最少的 8 类业务节点：

```text
ReferenceSource
  └─ EvidenceSnapshot
       ├─ ProductAsset
       ├─ CharacterAsset
       ├─ SceneAsset
       └─ PropAsset
            └─ StoryBeat
                 └─ ShotUnit
                      └─ MediaCandidate
```

所有节点共有：

- `id`
- `revision`
- `source_fingerprint`
- `status`
- `depends_on`
- `created_from`
- `user_overrides`

核心规则：

- 修改参考来源：使所有由旧参考派生且未被用户接管的节点失效。
- 修改人物服装：只失效引用该人物版本的镜头。
- 修改一个场景：只失效绑定该场景版本的镜头。
- 修改某一镜画面：只失效本镜视频和明确依赖本镜末帧的后续镜头。
- 用户手改字段拥有最高权威，自动重算不能覆盖。

## 六、控制代码冗余的实现方式

### 1. 不新建第二套生成链路

继续使用现有：

- `contextBuilder`
- `assetPlanService`
- `storyAdService`
- `referenceVideoAnalysisService`
- 现有任务、修订、自动保存和生成队列

精细化图谱只描述依赖和版本，不再实现一套新的生成 API。

### 2. 先拆旧文件，再增加界面

`new-story-ad-legacy-ui.js` 不再承载新业务逻辑。后续每个阶段遵守：

- 从旧文件移出的行数大于新增胶水代码行数。
- 业务规则进入已有领域模块。
- 旧文件只保留装配、路由和兼容入口。
- 边界测试继续限制核心文件行数。

建议拆出的现有职责：

- 会话与任务恢复 → `task-session.js`
- 参考来源状态 → `reference-video-analysis.js`
- 工作区导航 → `step-navigation.js` 演进为 workspace navigation
- 生成提交 → `generation-flow.js`
- 自动保存 → `task-persistence.js`

### 3. 一个状态，一个渲染器

禁止：

- 同一个参考分析分别保存在 DOM、全局变量、任务 context 三套不一致结构中。
- 新旧页面各写一套 `payload()`。
- 为人物、产品、场景分别复制上传、候选、选择、版本逻辑。

统一为：

- 领域状态是权威。
- DOM 是状态投影，不反向充当缓存。
- 资产卡片共用一个轻量 card renderer，通过类型配置差异字段。
- 服务端统一保存节点的 revision/fingerprint/dependency。

### 4. 代码体积门禁

每一阶段验收时检查：

- 核心旧 UI 文件不得净增长。
- 不允许新增第二个同义 API 或第二份状态字段。
- 新模块必须有唯一职责和对应测试。
- 删除重复提示、重复渲染和兼容分支后再增加功能。
- 普通页面只加载当前工作区模块；资产和导演高级功能继续懒加载。

## 七、分阶段落地

### P0：线上正确性

- 新建会话原子重置。
- 当前参考强绑定，失败不回退。
- 确定性事实与模型结果字段级合并。
- 浏览器和服务端付费前门禁。
- 生产部署、健康检查和目标任务只读核对。

### P1：参考与资产工作区

- 将当前参考区域改为单来源卡片。
- 分析结果先展示主体、环境、结构摘要，不直接塞入长文案。
- 人物、产品、场景、道具改成统一资产卡片。
- 增加来源与版本抽屉。

验收重点：不增加生成模型调用；旧 UI 核心文件净减少。

### P2：故事与镜头工作区

- 节拍条和镜头卡。
- 镜头显式绑定资产版本。
- 单镜局部重做与依赖失效。
- 高级关系图只读展示。

验收重点：修改一个资产时，失效范围可预测且不会整项目重跑。

### P3：生成与审核工作区

- 缺失、选中、全部三种生成范围。
- 失败定位到镜头和资产。
- 付费前一次性费用确认。
- 成片审核汇总。

验收重点：所有重试均可计算真实调用数，不自动重复付费。

## 八、最终验收指标

- 新任务旧内容串用：0。
- 当前参考失败后回退旧分析：0。
- 已识别事实被模型空字段删除：0。
- 未完成参考触发下游模型：0。
- 普通用户默认可见技术错误码：0。
- 同一状态重复提示位置：不超过 1 个。
- 局部修改导致无关资产重算：0。
- 旧核心 UI 文件：不净增长，并逐阶段下降。
- 新增模型调用：P1/P2 的结构改造本身为 0。
