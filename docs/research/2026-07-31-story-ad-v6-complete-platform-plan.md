# VIDO 剧情广告 V6：独立模块与完整制作工作台方案

> 日期：2026-07-31
> 状态：产品与交互方案；尚未进入业务代码实施
> 原型：[2026-07-31-story-ad-v6-complete-platform-prototype.html](./2026-07-31-story-ad-v6-complete-platform-prototype.html)
> 替代：V4、V5 原型不再作为实施依据

## 0、2026-07-31 反馈修订

本方案和原型已经根据第二轮界面反馈修正：

- 模块内部明确拆成三层：`剧情广告任务中心 → 新建创作页 → 项目工作台`。平台全局导航不属于剧情广告模块原型，界面中不再出现数字人广告或智能剪辑卡片。
- 剧情广告任务中心包含任务编号、项目内容、当前阶段、进度、更新时间、打开按钮，以及全部项目、进行中、等待处理、已完成、共享项目、资产库和回收站。
- 新建创作页沿用左侧完整制作导航；删除主内容区重复的“系统将建立的制作层”。
- 视频、链接、商品、人物/宠物、场景、LOGO、脚本均提供真正可点击的上传、粘贴或资产库引用按钮。
- 资产主卡由四列改为三列；人物详情扩到 980px，直接显示完整人物档案图，包含三视图、六种表情、服装、头盔、手套、鞋、材质、配色和驾驶姿态。
- 全模块支持亮色/暗色主题，使用同一结构和状态色，不维护两套页面。
- 工作流画布支持按住空白处直接移动画布、Ctrl+滚轮缩放、加减缩放、适应画布和小地图；浏览器横纵滚动条完全隐藏。

## 一、这次重构解决什么

V6 不再把剧情广告放进“数字人广告”的某个标签，也不再用固定的五六步页面掩盖真实制作过程。它是首页一级入口和独立项目空间，覆盖：

1. 任意起点：一句想法、已有脚本、参考视频、参考链接、已有资产均可开始。
2. 完整资产：单人、双人、多人、宠物/动物、商品、LOGO、道具、多场景分别管理。
3. 剧情可见：剧情方向、情节点、人物关系、商品角色和品牌结尾集中在“剧情室”。
4. 分镜可控：文字分镜和可选线稿分镜结合，先低成本确认构图，再生成关键帧。
5. 镜头精细：每镜绑定场景、区域、机位、景别、焦段、机位高度、角度、运镜路径、速度和时长。
6. 衔接明确：镜头之间有独立连续性关系和首尾帧审核，不只是一排互不相干的视频。
7. 工作流透明：所有项目成员都能看关系画布，节点可点击并跳回对应业务编辑页。

## 二、信息架构

### 2.1 剧情广告独立模块首页

- 剧情广告模块打开后直接进入自己的任务中心，不在模块内部重复展示其他产品模块。
- 任务中心是模块首页，负责新建、继续、筛选、共享、资产库与已完成项目。
- 每个任务必须显示稳定任务编号和明确的“打开”按钮。
- 新建任务只有一个主入口：任务中心内容区的“开始创作”。顶部栏只保留主题与账户，不重复放置“新建剧情广告”。
- 点击唯一的“开始创作”进入独立新建创作页；点击项目进入该项目上次停留的工作区。
- 独立项目中心建议路由：`/story-ad/`
- 新建项目建议路由：`/story-ad/new`
- 项目工作台建议路由：`/story-ad/projects/:taskId`
- 旧入口 `/digital-human?tab=new-story-ad` 保留一段迁移期，打开后跳转至新模块，不再双重维护页面。

剧情广告可以在底层复用平台登录、素材和生成基础设施，但模块界面、任务中心、路由和工作区均独立，不出现数字人广告业务入口或混合导航。

### 2.2 项目工作台导航

| 页面 | 用户在这里完成什么 | 主要产物 |
|---|---|---|
| 目标与材料 | 说明要制作什么、选择起点、补充可选材料 | brief、input references |
| 资产中心 | 建立并确认人、动物、商品、LOGO、场景和道具 | asset masters、identity contracts |
| 剧情室 | 选择剧情方向、编辑情节点、检查关系与品牌露出 | story blueprint、beats |
| 分镜台 | 把情节拆为镜头，查看线稿、绑定资产和衔接 | storyboard shots、sketches |
| 镜头设计 | 定义机位、景别、焦段、角度、运镜和首尾帧 | shot design、camera intent |
| 生成与成片 | 生成关键帧/视频、审核、合成声音字幕与 LOGO | clips、review、final |
| 工作流画布 | 查看资产、剧情、镜头、版本、阻塞和生成关系 | 项目图谱投影；不建立第二套状态 |

页面顶端只显示当前动作所需提示。技术参数、模型、费用和历史默认收进详情或高级设置，不在主路径反复提示。

### 2.3 新建创作页

新建创作不是弹窗，也不是任务中心中的小表单，而是完整创作工作台的第一个工作区：

- 左侧已经显示目标与材料、资产中心、剧情室、分镜台、镜头设计、生成与成片、工作流画布；
- 主区域只负责广告目标、三种创作起点和生成制作方案；
- 右侧材料区的每一项都有直接动作：
  - 参考视频：上传/更换；
  - 参考链接：粘贴链接；
  - 商品：本地上传/资产库引用；
  - 人物与宠物：上传/资产库引用；
  - 场景：图片、视频、描述或场景库；
  - LOGO：上传授权透明文件；
  - 脚本与分镜：粘贴文字/上传 DOCX、PDF。
- 所有材料依然可选，没有材料时只写一句创作目标即可继续。
- 不再显示与左侧导航重复的横向流程说明层。

## 三、资产中心的完整模型

### 3.1 人物与多人

- 每个人建立独立 `cast_asset`：`C01`、`C02`……不能把多人身份合并为一张母版。
- 支持单人、双人、3–12 人和无人模式。
- 每个人独立维护：面部、全身、体型、服装、发型、饰品、授权来源和版本。
- 多人同镜通过 `cast_group`/关系组合绑定：
  - 成员与角色关系；
  - 站位、前后景、座位；
  - 视线和互动；
  - 遮挡优先级；
  - 谁可被替换、谁必须出现。
- 组合关系只约束镜头，不产生新的“混合身份”。
- 人物详情默认展示完整档案板，而不是单张占位预览。档案板至少同时覆盖：
  - 正面、侧面、背面三视图；
  - 六种稳定表情；
  - 服装拆解；
  - 头盔、手套、鞋和随身物品；
  - 面料、缝线和关键结构细节；
  - 主色与辅助色；
  - 站姿、坐姿和剧情所需动作姿态。
- V6 原型中的赛车手档案图保存在 `docs/research/2026-07-31-story-ad-v6-race-driver-dossier.png`，仅作为界面和信息密度验证资产。

### 3.2 宠物和其他动物

- 动物是独立资产，不挂在人物备注里。
- 档案字段包括：物种、品种、体型、年龄感、毛色、稳定花纹、眼睛、耳尾特征、项圈/配饰、动作边界。
- 人宠同镜使用组合关系，分别校验人物身份和动物身份。
- 多只动物按 `A01`、`A02` 分开建档，避免花纹和体型串用。

### 3.3 商品

- 每个商品独立 `product_asset`，保存多视角、结构细节、材质、颜色、尺寸/相对比例和授权来源。
- 商品在剧情中必须声明角色：主角、关键道具、环境商品或片尾展示。
- 商品一致性审核独立于人物审核；镜头引用固定版本，如 `P01 V4`。

### 3.4 LOGO

- LOGO 作为独立授权资产管理，保存透明 PNG/SVG、色彩版本、安全区和最小尺寸。
- LOGO 不进入图片/视频模型作为可重绘主体。
- 只在后期合成阶段调用现有品牌叠加能力，避免拼写、几何和商标变形。
- 每次使用记录位置、尺寸、出现时长和源版本。

### 3.5 多场景、空间与机位

每个场景拥有稳定 `scene_id`，并包含：

- 空间母版：布局、材质、天气、时间和主光方向；
- 区域：`zone_id`，如山路入口、连续弯道、隧道出口；
- 机位：`camera_id`、空间坐标、朝向、高度和可见范围；
- 视角：`view_id`、景别、焦段、方向、目标说明；
- 场景路线：场景之间的时间、天气、光线和移动关系。

每个镜头只能绑定一个主场景，跨场景必须有切换原因和连续性策略。一个场景可以生成多机位、多景别，而不是重复生成互不相关的“场景图”。

## 四、剧情怎样生成、在哪里看

剧情集中在“剧情室”，不再埋在大文本框中。

1. 系统根据 brief、参考分析和已确认资产生成 2–3 个剧情方向。
2. 用户选择一个方向或添加自定义剧情。
3. 已选剧情显示：
   - 一句话剧情；
   - 开场、建立、推进、转折、收束；
   - 每个情节点的角色、商品、场景和时长；
   - 人物/动物关系；
   - 商品在剧情中的作用；
   - 品牌结尾规则。
4. 用户逐个情节点编辑，不必重写整篇。
5. 确认后，情节点转换为分镜任务；后续修改只标记受影响镜头，不覆盖已经确认且不受影响的内容。

## 五、线稿分镜如何结合

### 5.1 当前事实

平台现有故事蓝图、文字分镜、关键帧和视频链路可以复用，但当前剧情广告链路没有独立的“线稿分镜/animatic”产物类型和确认阶段。这是 V6 的新增能力，不应伪装成已经完成。

### 5.2 新增方式

新增轻量产物 `storyboard_sketch`，字段最少包含：

- `shot_id`
- `composition`
- `subject_positions`
- `screen_direction`
- `camera_hint`
- `source_storyboard_version`
- `image_artifact_id`
- `status`

数据流：

`剧情情节点 → 文字分镜 → 可选线稿 → 镜头设计 → 关键帧 → 视频`

- 复杂多人、动物互动、空间调度或跨场景镜头默认建议线稿。
- 简单商品特写、纯环境镜头可以跳过。
- 线稿只确认数量、站位、构图、动作和屏幕方向，不承担身份和材质精度。
- 线稿确认后，构图约束进入现有关键帧提示构建器；不另建一套生成服务。

## 六、机位、运镜和角度

“镜头设计”采用三栏界面：

- 左栏：镜头列表、场景和状态；
- 中栏：线稿、起始关键帧、结束关键帧、运镜路径、前后镜连续性；
- 右栏：结构化镜头参数。

每镜参数：

- 场景、区域、机位；
- 主体与版本；
- 景别起止；
- 焦段；
- 机位高度；
- 俯拍/平拍/仰拍角；
- 水平朝向；
- 运镜方式：固定、推、拉、摇、移、升降、跟拍、环绕、手持或组合；
- 运动路径、速度、加减速、持续时间；
- 起始帧/结束帧构图；
- 进入和离开画面的方向。

普通用户看到人类可理解的选择项；模型参数和内部 prompt 默认折叠。

## 七、镜头怎样衔接

每两个相邻镜头之间建立 `transition_bridge`，至少记录：

- 前镜尾帧和后镜首帧；
- 动作锚点；
- 视线方向；
- 屏幕运动方向；
- 主体位置与尺度；
- 场景轴线；
- 光线与色彩；
- 声音连续性；
- 切换策略。

可选策略：

- 硬切；
- 动作切；
- 视线匹配；
- 形状/颜色匹配；
- 建立镜头插入；
- 淡入淡出/叠化；
- J-cut、L-cut 或音效桥。

生成视频后复用现有转场审核，将前片尾帧和后片首帧并排检查；若不连续，优先只重做一个受影响镜头或调整转场，不整片重生。

## 八、所有人可见的工作流画布

### 8.1 权限结论

- 工作流不再设超管或调试权限。
- 能打开剧情广告项目的人，都能打开该项目的工作流。
- 工作流节点仅显示该用户已能访问的项目数据；不是一个跨项目后台。
- 费用、模型请求细节可放在折叠详情，但不以“是否能看画布”作为权限边界。

### 8.2 画布不是第二套编辑器

画布是项目真实数据的可视化投影：

- 数据源仍是任务、资产、剧情、分镜、镜头、artifact、revision 和 run；
- `graphProjectionService` 只负责把现有状态映射成节点和边；
- 点击节点打开详情抽屉；
- 抽屉展示预览、实体/版本/状态、来源、上游、下游、引用镜头和历史；
- “进入对应编辑页”跳回资产中心、剧情室、分镜台或镜头设计；
- 用户不直接在画布里手工修改业务真值，避免画布状态和业务状态分叉。

### 8.3 画布分组

1. 输入与目标；
2. 人物/动物/商品/LOGO/道具资产；
3. 多场景空间与机位；
4. 剧情、线稿、镜头和衔接；
5. 关键帧、视频、审核和成片。

支持缩放、适应画布、小地图、异常筛选、版本筛选和故事板切换。默认全屏，退出后回到原业务页，不占用普通页面的大篇幅。

画布视觉采用媒体节点优先：

- 分组只提供轻量灰色背景和标题，不使用厚重黑色边框；
- 节点本身取消额外黑色卡片框，直接显示图片、视频或文本产物预览；
- 标题和版本放在媒体预览下方；
- 分组尺寸紧贴实际节点，避免大面积无意义空框；
- 人物、商品和场景节点优先显示真实当前版本缩略图，而不是“人、景、产品”等文字占位。

画布交互直接对齐平台现有画布习惯：

- 按住空白区域拖拽平移；
- 按住画布直接平移，不显示浏览器滚动条；
- Ctrl/Command + 滚轮以鼠标位置缩放；
- 加号、减号进行固定步长缩放；
- “适应画布”恢复全局视野；
- 缩放范围建议 40%–160%；
- 节点点击优先于拖拽，不会误移动画布。

## 九、复用现有能力，控制代码冗余

### 9.1 直接复用

| 需求 | 复用现有能力 |
|---|---|
| 多人、无人、人宠模式 | `subjectAssetBundleService`、现有 cast mode |
| 宠物身份 | `petIdentityContractService`、person-pet spec |
| 商品一致性 | `productIdentityContractService` |
| LOGO | `brand-overlay.js`、`brandEndingService`、合成服务 |
| 多场景绑定 | `sceneBindingService` |
| 机位与视角 | `sceneViewStrategyService`、`shotDesignService` |
| 运镜与剪辑 | motion-aware edit、camera intent |
| 镜头衔接 | compose transition plan、transition review |
| 节点、边、版本、运行记录 | `videoCanvas` graph/revision/artifact/run 基础设施 |

### 9.2 只新增四个薄层

1. `story-ad` 独立模块 shell 和路由；
2. 统一 `StoryAdProjectBundle` 视图模型，把已有 task bundle 整理为页面所需结构；
3. `storyboard_sketch` 产物类型和薄编排步骤；
4. `graphProjectionService`，将真实业务状态投影到现有 VideoCanvas 图数据。

不要新增第二套人物、场景、镜头、任务、版本或费用存储；不要复制现有模型 adapter；不要让每个页面分别请求和拼装同一任务。

### 9.3 前端拆分

建议目录：

│   └── projectStore.js

一个 store、一个 API client、共享抽屉和媒体组件，避免继续扩展现有超长单文件。

### 9.4 与现有功能的逐页接线

V6 不是重写生成链路。新页面通过统一 store 消费现有任务和产物，写操作继续调用现有剧情广告接口；只有聚合读取、线稿产物和只读图谱需要新增薄接口。

| V6 页面 | 首次读取 | 现有写入/执行接口 | 权威数据 | 实施结论 |
|---|---|---|---|---|
| 任务中心 | `GET /api/new-story-ad/tasks` | `POST /api/new-story-ad/tasks`、`DELETE /tasks/:id` | 现有 task | 新 UI 直接复用，不新建任务表 |
| 目标与材料 | project bundle 中的 task/request/reference | `PUT /tasks/:id`、现有上传、参考链接和参考分析接口 | task request、reference analysis | 保留已经修复的参考来源隔离和分析门禁 |
| 资产中心 | `taskViewService`、`directorWorkspaceService` 的 people/scenes 投影 | 现有 `subject-assets`、person production、scene assets、prop routes | 现有人物、宠物、商品、场景、道具产物 | 只换组织方式，不复制资产服务 |
| 剧情室 | bundle 中的 blueprint、story setup | `POST/PUT /tasks/:id/blueprint`、现有 assist | `outputs.blueprint` | 剧情方向和情节点是现有蓝图的结构化视图 |
| 分镜台 | blueprint、storyboard table、连续性状态 | `POST/PUT /tasks/:id/storyboard` | `outputs.storyboard_table` | 文字分镜复用；只新增可选线稿产物 |
| 镜头设计 | storyboard、scene locks、shot design、continuity | 更新现有 storyboard/shot 结构；生成前仍走 `prepare-generation` | storyboard shot + scene binding | 不另建镜头表或第二套镜头状态 |
| 生成与成片 | keyframes、clips、QA、final video | 现有 keyframe contract、keyframes、video preflight、video、compose、cancel | 现有 generation outputs | 完整保留当前付费门禁、并发、失败恢复和 QA |
| 工作流画布 | 新增只读 graph projection | 不在画布直接写业务数据；节点跳回对应业务页 | 同一个 project bundle | 复用 VideoCanvas 渲染与交互，不复用其第二套项目存储 |

现有真实接口包括：

- 任务：`GET/POST /api/new-story-ad/tasks`、`GET/PUT /tasks/:id`；
- 参考：`reference-video-upload-sessions`、`reference-video-links`、`reference-video-analyses`；
- 资产：`subject-assets`、`person-production`、`person-dossiers`、`scene-assets` 和 prop routes；
- 剧情与分镜：`blueprint`、`script-package`、`storyboard`；
- 生成：`prepare-generation`、`keyframe-contract`、`keyframes`、`video/preflight`、`video`、`compose`；
- 恢复与监控：`progress`、`director-workspace`、cancel 和现有 generation 状态投影。

### 9.5 统一 Project Bundle，不让七个页面各自拼数据

新增一个只读聚合接口：

```text
GET /api/story-ad/projects/:taskId/bundle?sections=summary,assets,story,shots,media
```

它不经 HTTP 再调用旧接口，而是在服务端直接组合现有：

- `taskViewService`；
- `directorWorkspaceService`；
- `taskProgressProjectionService`；
- `taskBundleProjection.compactPublicTaskBundle`；
- 已有 task/output/storage repository。

返回的 `StoryAdProjectBundle` 至少包括：

```js
{
  project,
  reference,
  assets: { people, animals, products, logos, props, scenes, relations },
  story: { setup, blueprint, beats },
  storyboard: { shots, sketches, transitions },
  generation: { keyframes, clips, qa, finalVideo, progress },
  permissions,
  revisions
}
```

前端 `projectStore` 只保存这一份 bundle，并按 revision 做局部合并。生成轮询只请求 progress/changed sections，不重复下载全部人物档案和媒体列表。

所有写操作遵循同一规则：

1. 页面调用现有写接口；
2. 服务端写回现有 task/output；
3. 响应返回新的 revision 和受影响 section；
4. store 局部刷新；
5. 工作流图由新 bundle 重新投影。

禁止页面先改画布、再反向同步业务数据；禁止资产中心和工作流各维护一套版本号。

### 9.6 只新增的服务端文件

建议新增范围控制为：

```text
src/routes/storyAdWorkspace.js
src/services/storyAdWorkspace/projectBundleService.js
src/services/storyAdWorkspace/storyboardSketchService.js
src/services/storyAdWorkspace/graphProjectionService.js
```

- `storyAdWorkspace.js` 只提供 bundle、sketch 和 graph 三类薄接口，不承载生成业务。
- `projectBundleService.js` 只聚合现有 projection/repository，不持久化第二份数据。
- `storyboardSketchService.js` 把 `storyboard_sketch` 写入现有 task output/artifact 体系，并把确认后的构图约束交给现有关键帧 contract。
- `graphProjectionService.js` 只返回 VideoCanvas 兼容的 nodes/edges/status/targetRoute，不保存独立 graph project。

现有 `src/routes/newStoryAd.js` 不再继续扩大；后续只做兼容路由和已有业务修复。现有 `public/js/new-story-ad-legacy-ui.js` 不搬进新模块，新页面只通过共享 API client 调用服务端。

### 9.7 权限、迁移与灰度

当前剧情广告 API 挂在 `avatar` 权限下，VideoCanvas API 挂在 `aicanvas` 权限下。V6 不能让普通剧情广告成员直接读取 `/api/video-canvas`，否则会再次出现“只有部分人看得到工作流”的问题。

正确方式：

- `/api/story-ad/projects/:taskId/graph` 使用剧情广告模块权限和任务访问校验；
- 返回只读投影，不要求 `aicanvas` 权限；
- 前端只复用 VideoCanvas 的画布渲染、平移、缩放、节点和连线组件；
- 所有项目成员可查看图；能否修改资产、剧情、镜头仍由对应业务权限决定；
- 节点详情返回 `targetRoute`，点击后回到资产、剧情、分镜、镜头或成片页面编辑。

迁移采用同 ID、同数据、双入口灰度：

1. 功能开关仅把内部账号导向 `/story-ad/`；
2. 新任务中心读取现有 tasks，旧任务无需复制；
3. 新旧页面对同一任务执行只读 bundle 对比，字段和阶段一致后再扩大流量；
4. 新页面稳定后，旧 `/digital-human?tab=new-story-ad` 跳转新模块；
5. 最后删除旧 UI 绑定和重复样式，不删除现有服务、任务或历史产物。

### 9.8 防止再次冗余和加载变慢的硬门禁

当前旧入口的已核对基线：

- `public/js/new-story-ad-legacy-ui.js` 约 351 KiB、6241 行；
- 首次进入会顺序加载约 31 个核心脚本，合计约 278.5 KiB，之后还要加载旧 UI；
- 页面仍嵌在数字人工作台 HTML 中，模块未打开时也承担了模板和宿主页复杂度；
- 多个模块分别恢复、拼装和同步同一任务状态，容易形成重复请求与重复渲染。

V6 实施必须同时满足以下门禁，否则不允许替换旧入口。

#### 代码体积

- 新模块不得引用 `new-story-ad-legacy-ui.js`，不得复制其中的 DOM 模板或业务判断。
- 新增前端文件单文件原则上不超过 600 行；超过必须拆分，800 行为禁止合入线。
- 任务中心首屏新增 JS 原始体积不超过 100 KiB；进入项目后的 shell + 当前视图累计不超过 220 KiB。
- 非当前视图使用原生 `import()` 懒加载；资产生产、镜头生成、成片审查和画布代码不得进入任务中心首包。
- 共用 API、store、媒体预览、抽屉、状态标签和错误引导组件；相同业务规则不得在两个 view 中复制。

#### 请求和数据

- 任务中心首屏只允许 1 个项目列表业务请求；统计数字由同一响应返回，不另发四个计数请求。
- 打开项目首屏只允许 1 个 bundle 请求；progress 轮询和当前 section 增量请求除外。
- project bundle 默认不内嵌原图、完整人物档案、视频二进制、长 prompt 和完整历史版本，只返回缩略图 URL、摘要和当前有效版本。
- 人物多视图、候选图、版本历史、调用费用和画布节点详情在用户打开抽屉或对应页面后再请求。
- 所有媒体必须使用缩略图、分页或虚拟列表；禁止一次把十几张原图解码到不可见区域。
- store 按 revision 合并，切换工作区不得重复拉取没有变化的 section。

#### 渲染和交互

- 视图切换只切换当前路由组件，不重新创建全局 store、轮询器或媒体播放器。
- 每个任务只能存在一个 progress 轮询器；离开生成页后降频，离开项目后立即释放。
- 列表、画布和候选媒体使用事件委托，禁止给每张卡重复注册全局监听器。
- 画布只渲染当前可视范围及附近节点；大型项目采用分组折叠和节点虚拟化。
- 主题只切换 CSS token，不维护两套 DOM。

#### 性能验收预算

- 生产环境移动网络模拟下：任务中心 LCP 不高于 2.5 秒，INP 不高于 200 毫秒。
- 已有任务恢复：bundle API P95 不高于 500 毫秒；不含媒体下载的工作区可操作时间不高于 1.5 秒。
- 页面切换后不得出现超过 50 毫秒的重复长任务；连续切换七个工作区后监听器和轮询器数量不增长。
- 50 个任务的任务中心和 100 个工作流节点的项目必须通过滚动、拖动画布和内存稳定性测试。
- 亮色、暗色以及 1366、1600、1920 三档宽度均执行视觉回归。

#### 自动门禁

每个阶段合入前必须输出：

1. 新增/删除文件与行数；
2. 首屏和各路由实际加载的 JS/CSS 字节数；
3. 首屏业务请求数量和 bundle 响应体积；
4. Lighthouse 或等价浏览器性能结果；
5. 重复代码扫描结果；
6. 路由反复切换后的监听器、轮询器和内存对比；
7. 新旧页面读取同一任务的字段一致性报告。

任何一项超预算都必须先解释并拆分，不能以“后续优化”作为上线条件。

## 十、提示和交互降噪

主路径只保留三类信息：

1. 现在要做什么；
2. 为什么被阻塞；
3. 下一步按钮。

以下内容默认收起：

- 技术参数和原始 prompt；
- 模型名称；
- 调用和费用拆分；
- 哈希、artifact ID 和内部错误栈；
- 高级镜头参数；
- 版本与生成历史。

错误文案必须转换为动作，例如：

- 不显示：`source_product_missing`
- 显示：`没有找到商品参考。添加商品图片，或选择“本片不需要商品”。`

页面不重复出现“可选”“不会收费”等长提示；在首次出现的位置说清楚，后面使用简短状态。

### 双主题

- 跟随平台已有亮色/暗色偏好，并把选择写入用户界面设置。
- 两种主题只切换 design token，不复制 HTML、组件或业务逻辑。
- 媒体、状态、选中边框和风险色在两种主题中保持同一语义。
- 画布在亮色主题下使用浅灰网格、白色分组和高对比节点；暗色主题保持竞品式深色制作空间。
- 导航编号、状态标签、剧情卡、分镜表头、镜头表单和工作流工具栏全部使用主题 token，禁止组件内直接写死深色背景。
- 亮色主题中的深色区域只用于视频、图片或镜头预览画面；任何文字型状态、表单和操作卡都必须保持浅色高对比。

## 十一、实施顺序

### Phase 0：先关闭线上错数据路径

完成参考文件归属、任务隔离、分析结果绑定和回归验证后，才允许继续付费生成。该修复属于独立线上问题，不由 UI 重构替代。

### Phase 1：独立模块壳与统一数据

- 首页入口和 `/story-ad/`；
- 旧入口跳转；
- 项目列表与工作台；
- 单一 project bundle/store；
- 不改生成链路。

### Phase 2：资产中心和剧情室

- 完整资产类型；
- 多主体关系；
- 场景/机位管理；
- 剧情方向与情节点；
- 继续复用现有任务和资产服务。

### Phase 3：线稿、镜头设计和衔接

- 新增线稿 artifact；
- 结构化镜头设计；
- transition bridge；
- 接入现有关键帧、视频与转场审核。

### Phase 4：所有人可见的工作流

- 业务图谱投影；
- 节点详情抽屉；
- 故事板/异常/版本视图；
- 与业务页双向跳转。

### Phase 5：迁移与删除冗余

- 迁移旧任务；
- 删除旧剧情广告标签页和重复状态；
- 保留兼容 API 一段时间后再清理；
- 基于真实使用数据继续降噪。

## 十二、验收标准

1. 用户不上传任何材料，只写一句需求也能建立项目。
2. 用户能在一个项目中分别确认 3–12 人、多个动物、商品、LOGO、道具和多个场景。
3. 任意资产卡和工作流节点都能打开详情并回到对应编辑页。
4. 剧情有独立可见页面，情节点能明确引用资产和场景。
5. 线稿能逐镜生成/跳过，确认后约束关键帧，不创建重复任务状态。
6. 每镜可查看场景、机位、景别、焦段、角度、运镜路径和相邻衔接。
7. 生成后可并排检查前片尾帧与后片首帧。
8. 所有项目成员可见工作流，不再出现超管专用入口。
9. LOGO 仅通过授权源文件后期叠加。
10. 项目 bundle、任务、资产、artifact 和图谱只有一套事实来源。
11. 任务中心只发出一个列表业务请求；项目首屏只发出一个 bundle 业务请求。
12. 新模块不加载 `new-story-ad-legacy-ui.js`，任务中心和当前工作区 JS 体积均满足 9.8 性能预算。
13. 连续切换七个工作区后，轮询器、全局监听器和媒体播放器实例数不增长。
14. 50 个任务、100 个画布节点和十二张人物档案图场景通过加载、滚动、拖拽与内存稳定性验收。
