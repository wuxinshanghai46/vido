# 剧情广告 V5：一体化制作台与竞品式制作记录

> **已由 V6 替代：** V5 未覆盖多人/动物/LOGO、多场景机位、线稿分镜、完整衔接和全员工作流，不再作为实施依据。请使用 [V6 完整方案](./2026-07-31-story-ad-v6-complete-platform-plan.md) 与 [V6 交互原型](./2026-07-31-story-ad-v6-complete-platform-prototype.html)。

> 日期：2026-07-31
> 状态：重新梳理后的产品、界面与代码实施方案；V4 原型作废；尚未修改业务代码
> 交互原型：[打开 V5 一体化制作台](./2026-07-31-story-ad-v5-integrated-workbench-prototype.html)

## 一、为什么 V4 必须作废

V4 有两个结构性错误：

1. 普通用户界面仍然把现有能力重新包装成步骤和长表单，没有明确告诉用户当前要做什么、下一步做什么。
2. 所谓“关系画布”只是横向状态卡片，不是竞品那种以图片、视频和文本产物为节点的制作网络，也无法自然关联当前生成能力。

V5 不在 V4 上继续修补。普通制作与授权制作记录重新分层。

## 二、竞品再次核对后的确认事实

本轮使用已登录页面只读检查了保时捷 718 项目，没有复制项目、没有提交表单、没有触发生成。

### 2.1 工作流

- 工作流是可缩放的大型媒体节点画布，不是步骤导航。
- 当前项目可见 18 个分组。
- 分组内混合图片、视频、裁剪、旋转与其他处理节点。
- 节点之间有真实连线；多个资产可以合流到一个镜头，也可以从一个母版产生多个候选。
- 画布提供小地图、缩放比例、连线显示开关。
- 画布默认使用很低缩放比例查看全局，需要时放大局部分组。

### 2.2 故事板

- 故事板与工作流是同一项目的两种视图。
- 左侧主要浏览图片和已选资产，右侧浏览视频结果。
- 故事板不是第二套生成数据，只是把工作流产物按图片、视频和选中状态重新投影。

### 2.3 对 VIDO 的真正启发

需要学习的不是竞品的黑色背景，而是：

```text
同一份产物数据
  ├─ 普通制作台：告诉用户现在该做什么
  ├─ 关系画布：查看所有节点、候选、分支、合流和版本
  └─ 故事板：查看已选图片与视频结果
```

## 三、V5 总体界面

普通用户只看到五个清晰工作区：

1. 制作说明。
2. 角色与场景。
3. 剧情与分镜。
4. 镜头制作。
5. 成片交付。

授权用户额外看到“制作记录”，其中包含：

- 关系画布。
- 故事板。

关系画布和故事板默认关闭，不占普通工作区。

## 四、工作区一：制作说明

### 4.1 首要问题

第一屏只先问：

> 这支广告要讲什么？

用户可以只写一句话开始。

### 4.2 补充材料全部可选

不再要求用户先选择一种创作模式，也不假设一定有参考视频。

补充材料可以任意组合：

- 产品或广告主体。
- 人物参考或演员库。
- 场景参考。
- 参考视频。
- 参考链接。
- 已有文案、故事或分镜。

系统根据实际添加的材料选择现有能力：

- 没有参考：按广告目标直接规划资产。
- 有视频：调用参考视频上传和分析。
- 有链接：调用公开视频链接读取。
- 有产品图：进入商品或主体锁定。
- 有人物：进入真人来源或演员库。
- 有脚本：直接作为剧情与分镜输入。

### 4.3 页面只保留一个主要动作

主要动作是“生成制作方案”。

生成后显示：

- 预计人物、产品、场景和镜头。
- 系统准备采用的制作顺序。
- 下一步唯一要处理的对象。

## 五、工作区二：角色与场景

页面不再展示当前生产界面的全部长表单。

### 5.1 默认只展示资产卡

- 人物母版。
- 产品母版。
- 场景母版。
- 独立道具。

每张卡只显示：

- 当前图片。
- 来源。
- 当前版本。
- 是否确认。
- 下一步操作。

### 5.2 候选选择在右侧处理

选择某张资产卡后，右侧显示：

- 候选图片。
- 当前选中项。
- 生成补充视角。
- 替换来源。
- 确认母版。

### 5.3 技术字段收起

当前界面中的主表面结构、拼缝策略、饰面分布、平面数量等字段全部进入“高级空间控制”。

默认情况下用户只处理：

- 空间是什么。
- 布局是什么。
- 材质与光线是什么。
- 哪个候选最符合剧情。

只有任务确实需要结构约束时才展开对应高级字段。

## 六、工作区三：剧情与分镜

顶部先展示五段故事节拍：

- 开场。
- 人物或主体建立。
- 推进。
- 高潮。
- 商业收束。

下方分镜表每行只展示：

- 镜头编号。
- 画面预览。
- 当前镜头发生什么。
- 使用哪些已确认资产。
- 当前是否可制作。

用户修改镜头时，不需要理解内部关键帧合同或技术机位。

## 七、工作区四：镜头制作

每个镜头都对应同一条可见链：

```text
已确认资产 → 关键帧候选 → 已选关键帧 → 视频候选 → 已选视频 → 审核
```

页面支持：

- 生成关键帧。
- 选择关键帧。
- 生成视频。
- 选择视频。
- 只生成缺失镜头。
- 查看阻塞原因。

提交前只显示真实调用次数和预计费用。被上游阻塞的镜头不产生调用。

## 八、工作区五：成片交付

主要内容：

- 成片预览。
- 镜头完成度。
- 人物一致性。
- 产品一致性。
- 转场连续性。
- 声音和字幕。
- 导出。

内部 QA 细节只在“查看审核详情”中展开。

## 九、授权制作记录

### 9.1 权限

入口只对以下人员显示：

- 超管。
- 拥有 `luxury_ad_pipeline_debug` 权限的人员。

普通用户：

- 没有入口。
- 不请求关系图接口。
- 不接收内部节点、模型、费用和错误数据。

### 9.2 关系画布

关系画布必须与竞品一样以媒体产物为中心，而不是以业务步骤为中心。

分组示例：

- 输入与目标。
- 人物 C01。
- 产品 P01。
- 场景 S01、S03。
- 镜头 SH01。
- 镜头 SH02。
- 镜头 SH05。
- 声音、审核与成片。

节点示例：

- 用户目标文本。
- 上传产品图。
- 参考视频及分析。
- 人物来源图。
- 人物三视图。
- 造型候选。
- 产品多视图。
- 场景候选。
- 已选母版。
- 分镜文本。
- 关键帧候选。
- 已选关键帧。
- 视频候选。
- 已选视频。
- QA 结果。
- 最终成片。

画布提供：

- 拖动画布。
- 缩放。
- 适应全图。
- 小地图。
- 显示或隐藏连线。
- 只看异常。
- 只看当前版本。
- 按人物、场景或镜头聚焦。

首期只读。不能在调试画布中直接修改普通用户的业务数据。

### 9.3 故事板

故事板使用与关系画布相同的节点和产物：

- 左侧：已选人物、产品、场景、关键帧。
- 右侧：已选视频片段。
- 按镜头顺序排列。
- 默认不显示失败候选和历史版本。

## 十一、复用现有视频画布，禁止新造执行链

项目已经存在：

- `src/services/videoCanvas/graphService.js`
- `src/services/videoCanvas/nodeCatalog.js`
- `src/services/videoCanvas/projectRepository.js`
- `src/services/videoCanvas/artifactRepository.js`
- `src/services/videoCanvas/runRepository.js`
- `public/js/video-canvas/graph/editor-adapter.js`
- 文字、图片、人物、视频、声音、合成和控制节点执行器。

因此 V5 不创建第二套画布后端。

### 11.1 只新增一个投影服务

建议新增：

```text
src/services/newStoryAd/storyAdCanvasProjectionService.js
```

职责只有：

1. 读取 `taskViewService.publicTaskBundle(taskId)`。
2. 把当前任务的文本、资产、候选、选择、视频、审核和成片转换为现有 VideoCanvas graph。
3. 将现有媒体 URL 注册为 VideoCanvas artifact 引用，不复制媒体文件。
4. 计算投影指纹；内容没有变化时不创建新 revision。

### 11.2 不增加第二套业务状态

权威状态仍然是 New Story Ad 的：

- task。
- outputs。
- artifacts。
- reviews。
- generation runs。

VideoCanvas 只保存：

- 布局位置。
- 分组。
- 节点引用。
- 边。
- 画布版本。

节点 `config` 中保存来源引用：

```json
{
  "source": {
    "business": "new-story-ad",
    "taskId": "task-id",
    "entityType": "scene_asset",
    "entityId": "S03",
    "outputKind": "scene_assets"
  },
  "ui": {
    "groupId": "scene-S03",
    "thumbnailUrl": "/api/...",
    "readOnly": true
  }
}
```

不新增人物表、场景表、镜头表或视频表。

### 11.3 接口

建议只新增一个只读入口：

```text
GET /api/new-story-ad/tasks/:id/production-record
```

返回：

- graph。
- storyboardProjection。
- revision。
- filters。
- permission。

该接口必须同时满足：

- 当前用户拥有剧情广告任务访问权。
- 当前用户为 admin，或拥有 `luxury_ad_pipeline_debug`。

普通页面不调用此接口。

## 十二、代码体积与冗余门禁

实施时必须满足：

1. 不复制 `new-story-ad-legacy-ui.js`。
2. 不新写第二套任务保存、媒体仓库、运行队列、费用或幂等逻辑。
3. 普通工作区通过一个 V5 store 读取 `publicTaskBundle`。
4. 旧模块按能力接入，而不是把实现复制到 V5。
5. 画布只增加投影适配器和必要的媒体节点渲染。
6. V5 稳定后删除旧长表单渲染和重复提示；目标是总代码净减少。

## 十三、实施顺序

### M0：状态和路由适配

- 定义 V5 store。
- 把现有 task bundle 适配成五个工作区 view model。
- 不修改生成服务。

### M1：制作说明

- 上线一句话目标与可选材料。
- 复用上传、链接、分析、产品和脚本入口。

### M2：角色与场景

- 将现有人物、产品、场景和道具功能改成卡片与候选选择。
- 高级结构字段默认收起。

### M3：剧情与分镜

- 复用蓝图和分镜接口。
- 增加资产引用和阻塞状态。

### M4：镜头与成片

- 复用关键帧、视频、TTS 和合成。
- 保留现有费用、幂等、QA 和恢复门禁。

### M5：制作记录

- 新增 Story Ad → VideoCanvas 只读投影。
- 扩展现有画布前端支持分组、媒体缩略图、小地图和只读模式。
- 故事板使用同一投影结果。

### M6：清理

- 移除旧六步长表单。
- 删除重复提示和重复状态判断。
- 完整回归后再关闭 V3。

## 十四、完成定义

只有以下全部成立才算完成：

- 无参考、仅参考链接、仅产品图、仅脚本和混合材料都能创建任务。
- 人物、产品、场景都能真实生成、选择和锁定。
- 分镜明确引用已锁定资产。
- 镜头能看到关键帧与视频候选链。
- 关系画布与故事板来自同一任务数据。
- 画布节点能追溯到当前功能、接口、产物和版本。
- 普通用户无法获得制作记录数据。
- 没有第二套业务状态、付费链路或媒体存储。
- 回归、静态检查、部署健康和生产只读核对全部通过。
