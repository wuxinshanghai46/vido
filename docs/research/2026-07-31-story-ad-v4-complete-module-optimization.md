## 一、最终范围

本轮不是只优化“资产准备”，而是重构整个剧情广告模块：

```text
进入剧情广告
  → 参考与目标
  → 资产准备
  → 故事与镜头
  → 生成与审核
  → 成片导出
```

同时提供受权限控制的生产概览与关系画布：

```text
证据 → 资产 → 镜头关键帧 → 视频 → 审核
```

普通用户只使用四个工作区。超管与授权人员先打开右侧生产概览，需要检查真实依赖关系时再主动进入关系画布。

## 三、统一页面外壳

### 3.1 固定区域

- 顶部：模块名称、项目名称、保存状态、任务中心、用户入口。
- 左侧：四个工作区和真实项目完成度。
- 中间：当前工作区。
- 右侧：对象详情抽屉，只有需要编辑具体人物、场景或镜头时出现。
- 超管链路：独立右侧抽屉，关闭时完全不占空间。

### 3.2 删除的全局元素

- 横向六步大卡片。
- 顶部重复说明整个流程的长句。
- 同一状态同时出现在进度条、卡片、Toast 和弹窗。
- 普通用户可见的模型名、节点名、内部错误码和供应商状态。
- 页面常驻的高级参数区。
- 普通用户无权访问却仍然渲染的技术组件。

### 3.3 导航规则

- 四个工作区长期可返回，不以“已完成步骤不可修改”限制用户。
- 左侧完成度由权威任务状态计算，不由 DOM 是否出现内容判断。
- 工作区可以查看，但付费动作受资产锁定和服务端门禁约束。
- 刷新、退出重进和跨电脑恢复后，仍停留在上次工作的对象或唯一阻塞项。

## 四、工作区一：参考与目标

### 4.1 页面目标

确认：

- 用户这次真正想制作什么。
- 用户选择从想法、参考、已有素材还是脚本开始。
- 可选参考来源及其中的确定性事实。
- 下一阶段需要建立的资产清单。

### 4.2 首屏内容

第一屏先显示“这次想做什么”，提供四个平级入口：

1. 从一个想法开始。
2. 借鉴一个参考。
3. 使用已有素材。
4. 根据脚本制作。

四种方式都先填写“描述你想制作的广告”，不能把上传视频作为默认前置条件。

只有选择“借鉴一个参考”时，才展开参考材料区：

- 上传本地视频。
- 粘贴参考链接。
- 从项目素材中选择。
- 显示当前来源、分析状态和替换入口。

参考材料区明确标注“可选，不添加也能继续”。选择其他三种方式后，整个参考上传与分析区域隐藏，不留下无关提示。

最后显示创作蓝图预览：

- 人物数量。
- 产品数量。
- 场景清单。
- 道具清单。

### 4.3 状态与门禁

入口主状态：

```text
选择创作方式 → 描述目标 → 确认方向 → 生成资产清单
```

仅参考模式增加独立子状态：

```text
未添加 → 已上传/已引用 → 分析中 → 分析完成
                              ↘ 分析失败
```

- 新参考一旦选择，旧分析立即失效。
- 失败不回退旧结果。
- 分析完成前不自动写入广告目标。
- 没有参考时可以按用户目标正常进入资产准备。
- 只有明确声明“依赖参考”的资产生成，才受参考分析门禁约束。
- 所有付费动作再次由服务端确认当前参考状态。

### 4.4 页面提示

只显示：

- 当前分析状态。
- 唯一失败原因与重新分析动作。
- 参考事实与用户目标冲突时的字段级确认。

不显示：

- `source_product_missing` 等内部错误码。
- 模型返回的原始长文本。
- “系统将自动识别……”类长期说明。

## 五、工作区二：资产准备

### 5.1 页面目标

真正产出并锁定：

- 人物连续性包。
- 产品身份包。
- 场景空间包。
- 必需道具。

不是只保存人物和场景描述。

### 5.2 首页结构

顶部：

```text
人物 1/1    产品 1/1    场景 2/3
```

第一块永远是唯一待处理项：

```text
场景 S03 尚未选择母版                         [选择母版]
```

下方展示已完成资产卡。

没有阻塞时，“待处理”区域自动消失。

### 5.3 人物详情

每个人物必须管理：

- 人物概念候选。
- 当前人物母版。
- 脸部三视图。
- 全身三视图。
- 造型版本。
- 服装、头盔、眼镜、面罩等遮挡补充。
- 被哪些镜头引用。
- 一致性状态。

核心动作：

- 选择人物母版。
- 补齐脸部或全身三视图。
- 新增造型。
- 创建新版本。
- 查看影响范围。

### 5.4 场景详情

每个独立物理空间必须管理：

- 场景母版候选。
- 当前母版。
- 时间、天气、光向、材质和空间布局。
- 故事需要的建立位、反打位、交互位和细节位。
- 被哪些镜头引用。
- 连续性状态。

场景母版中不嵌入故事人物和产品。人物/产品入景后的画面归镜头关键帧。

### 5.5 产品详情

- 产品母版。
- 故事所需多角度。
- Logo、型号、结构、材质等不可变特征。
- 关键局部。
- 禁止变化项。
- 被哪些镜头引用。

### 5.6 候选与版本

- 候选：同一版本中的多个结果。
- 选择：候选中确定一个当前结果。
- 锁定：允许镜头消费。
- 修订：产生新版本，不覆盖旧版本。

普通用户只看到：

- 生成中。
- 请选择一个。
- 已锁定。
- 需要处理。

## 六、工作区三：故事与镜头

### 6.1 页面目标

把叙事和生产拆开：

- 故事节拍决定为什么拍。
- 镜头决定拍什么、使用哪些资产和如何连续。
- 关键帧决定视频生成的视觉起点。

### 6.2 三栏结构

左侧故事节拍：

- 建立悬念。
- 出发。
- 性能展示。
- 情绪顶点。
- 产品收束。

中间镜头列表：

- 镜头编号和名称。
- 关键帧预览。
- 一句话动作。
- 人物/造型、产品、场景/机位标签。
- 当前状态。

右侧镜头详情：

- 时长。
- 景别、机位和运动。
- 连续性。
- 关键帧候选。
- 单镜重做。

### 6.3 镜头显式绑定

每个镜头必须绑定：

- `story_beat_id`
- `character_revision_id`
- `look_revision_id`
- `product_revision_id`
- `scene_revision_id`
- `scene_view_id`
- `prop_revision_ids`
- `previous_shot_dependency`

缺少必需绑定时，不能触发关键帧或视频调用。

### 6.4 局部重做

重做一个镜头只影响：

- 当前镜头的关键帧和视频候选。
- 明确引用当前镜头末帧的后继镜头。

不能整项目重跑，也不能使无关人物和场景失效。

## 七、工作区四：生成与审核

### 7.1 页面目标

- 显示每个镜头的生成与审核状态。
- 只生成缺失或选中的镜头。
- 在真正付费前统一确认一次。
- 将失败定位到具体镜头与资产。

### 7.2 左侧镜头审核列表

每行显示：

- 镜头编号。
- 当前视频预览。
- 生成版本。
- 画面、连续性和视频审核摘要。
- 唯一下一步动作。

状态：

- 通过。
- 等待关键帧。
- 等待上游。
- 生成中。
- 需要处理。
- 已取消。

### 7.3 右侧成片区

- 当前成片预览。
- 当前时长。
- 完成镜头数。
- 活动任务数。
- 人物连续性、产品一致性、音画和字幕审核。
- 导出动作。

### 7.4 费用与重试

- “生成选中镜头”和“生成全部缺失镜头”分开。
- 提交前显示真实调用数量和费用预估。
- 同一镜头同一幂等键不能重复计费。
- 页面刷新不能自动重新提交。
- 网络恢复只能查询已有任务，不能默认创建新任务。

## 八、超管生产概览与关系画布

### 8.1 默认形态

- 默认完全隐藏，普通工作区占满可用宽度。
- 超管点击“生产概览”后，打开 520px 右侧抽屉。
- 抽屉提供“收起”和“关闭”两个明确动作。
- “收起”后只保留 54px 右侧竖向标签，可一键重新展开。
- “关闭”后不占任何空间；下一次必须从左侧权限入口重新打开。
- 打开状态叠加在当前工作区，不改变主页面结构。
- 关闭时不请求或加载链路数据。
- 不显示无限画布。

### 8.2 内容

纵向四组：

1. 证据与目标。
2. 基础资产包。
3. 镜头与关键帧。
4. 视频与审核。

组内使用紧凑状态标签，异常使用琥珀色，失败使用红色。

底部显示：

- 图片调用数。
- 视频调用数。
- 重复计费数。
- 当前活动任务。
- “打开关系画布”入口；没有 `story_ad.canvas.manage` 权限时不渲染。

### 8.3 筛选

- 全部。
- 仅异常。
- 调用与费用。
- 历史版本。

普通查看者不需要拖节点或调整布局。

### 8.4 深度全图

只有满足以下条件才提供“展开全图”：

- 用户拥有 `story_ad.canvas.manage`。
- 当前任务存在复杂分支、并发或多次版本回退。
- 用户主动从生产概览进入。

全图是二级排错工具，不是剧情广告模块的常驻页面。

关系画布按五个语义层组织：

1. 证据与目标。
2. 人物、产品与场景资产。
3. 故事、镜头与关键帧。
4. 视频与声音。
5. 审核与成片。

画布中的人物、产品、场景、镜头、关键帧、视频和审核都是独立节点，边必须显示真实的一对多、多对一、分支和合流关系，不能用纵向状态列表冒充工作流。顶部提供当前版本、异常、人物分支、场景分支和镜头筛选；右侧只显示选中节点的最早阻塞点、下游影响、调用次数与返回处理入口。画布提供“收起到生产概览”和“关闭”，普通查看者不需要拖拽节点。

工作流不是第二套业务编辑器：节点和连线全部由统一产物关系接口只读投影，画布本身不保存人物、场景、镜头或生成状态。

## 九、权限

```text
super_admin
OR (
  task_access
  AND story_ad.canvas.view/audit/manage
)
```

- `view`：链路和节点摘要。
- `audit`：调用、费用、错误、重试和版本。
- `manage`：失效、重跑、切换版本及展开全图。

前端隐藏入口不等于权限控制。服务端必须：

- 无权限返回 403。
- 不返回链路 JSON。
- 不返回完整提示词、费用和错误详情。
- 写入权限查看和高级操作审计。

## 十二、服务端改动清单

### 12.1 继续复用

现有服务已经覆盖大量正确能力，不重写：

- 参考来源与证据合并。
- 人物身份、档案和一致性 QA。
- 产品身份与一致性 QA。
- 场景空间、视图、图集、绑定和检查点。
- 故事板、镜头设计和连续性门禁。
- 关键帧契约、提交、并发和失败处理。
- 视频费用授权、提交、并发、血缘和质量审核。
- 任务修订、保存和恢复。

### 12.2 投影层

以现有 `directorWorkspaceService` 为基础，收敛为统一工作区投影：

```text
task + reference + assets + story + generation
  → workspace projection
  → V4 store
```

兼容期继续保留现有 `/director-workspace` 路由别名，避免一次性改完全部调用方。

### 12.3 链路接口

只新增一个受权限控制的只读投影：

```text
GET /api/new-story-ad/tasks/:taskId/lineage
```

参数：

- `mode=current|history|errors|cost`
- `compact=1`

默认只返回当前有效业务节点和边。

不新增：

- V4 专用生成接口。
- V4 专用任务保存接口。
- 第二套人物、场景或镜头接口。
- 第二份媒体记录。

### 12.4 写操作

生产概览和关系画布首期只读。

后续高级写操作继续调用现有领域服务，并增加：

- `manage` 权限。
- 任务访问权。
- 版本和 edit sequence 校验。
- 幂等键。
- 审计日志。

## 十三、状态与数据约束

### 13.1 单一权威状态

```text
服务端任务/修订
  → V4 task-store
  → 工作区选择器
  → DOM
```

禁止 DOM 反向充当缓存。

### 13.2 统一资产契约

人物、产品、场景和道具共用：

- `id`
- `kind`
- `revision`
- `status`
- `candidate_ids`
- `selected_candidate_id`
- `locked_at`
- `source_fingerprint`
- `depends_on`
- `used_by_shot_ids`

类型差异放在 `spec`，不复制生命周期代码。

### 13.3 修改影响

- 更换参考：使旧参考自动派生且未被人工接管的内容失效。
- 修改人物造型：只影响绑定该造型版本的镜头。
- 修改场景：只影响绑定该场景版本和机位的镜头。
- 重做关键帧：只影响本镜头视频和显式后继。
- 选择候选：不创建新版本。
- 修改并重新生成：创建新版本。

## 十四、提示与交互改动

一个事件只能占一个主要位置：

- 持续状态：对象旁边。
- 短暂完成反馈：Toast。
- 付费、覆盖、删除和失效：确认弹窗。
- 技术详情：详情抽屉或超管链路。

所有错误文案采用：

```text
发生了什么 + 用户现在能做什么
```

例如：

```text
尚未确认当前视频中的产品主体。请重新分析，或删除参考视频后按文字目标继续。
```

不显示：

```text
REFERENCE_VIDEO_ANALYSIS_SEMANTIC_INVALID: source_product_missing
```

## 十五、迁移顺序

### M0：契约盘点

- 冻结当前任务、保存、恢复、生成和审核契约。
- 建立关键文件行数与重复逻辑基线。
- 为 V4 加功能开关。

### M1：外壳与参考

- 新外壳、左侧导航、唯一 store。
- 迁移参考上传、分析、目标和蓝图预览。
- 不新增模型调用。

### M2：资产

- 统一资产卡和候选选择。
- 人物、产品、场景真实生成与锁定。
- 移出 `scene-assets.js` 和 `subject-assets-ui.js` 的 UI。

### M3：故事与镜头

- 节拍、镜头列表、详情抽屉。
- 显式资产版本绑定。
- 关键帧候选和单镜重做。

### M4：生成与审核

- 生成范围、费用确认、任务恢复。
- 镜头审核列表和成片区。

### M5：紧凑链路

- 服务端 ACL。
- compact lineage 投影。
- 520px 右侧抽屉。

### M6：旧界面退役

- V4 完整回归通过。
- 新任务默认 V4。
- 历史任务兼容。
- 删除 V3 渲染和重复状态。

## 十六、代码冗余门禁

- 新工作区不能复制 API、保存或任务轮询。
- 同义状态字段只能保留一个。
- 迁入 V4 的旧渲染必须在同阶段删除。
- 旧核心 UI 文件每阶段净减少。
- 兼容层只能转换字段，不能写业务规则。
- 普通页面不加载链路运行时。
- 链路接口不复制媒体、提示词或任务状态。
- 双轨期结束后删除 V3，不允许永久两套实现。

## 十七、完整验收

### 正确性

- 新任务不会恢复旧任务内容。
- 新参考不会回退旧分析。
- 人物和场景真实生成并可选择、锁定。
- 镜头显式绑定资产版本。
- 单资产修改不会使无关镜头失效。
- 未满足门禁时模型调用为 0。

### 恢复

- 刷新、退出重进和跨电脑恢复一致。
- 活动任务只恢复查询，不重复提交。
- 并发保存遵守 revision/edit sequence。

### 权限

- 普通用户没有链路入口。
- 无权限直链和接口均为 403。
- `view/audit/manage` 范围正确。
- 高级操作有审计。

### 体验

- 每页只有一个主要下一步动作。
- 同一状态不重复提示。
- 普通用户技术错误码为 0。
- 超管链路关闭时不占用工作区。
- 全屏画布不是日常入口。

### 代码

- 完整测试、语法检查和结构边界通过。
- 旧核心 UI 文件净减少。
- 没有第二套生成或保存接口。
- 没有已知重复付费和状态覆盖路径。

## 十八、实施结论

完整优化不是“把旧页面换个皮肤”，而是：

1. 以四个工作区重新组织所有现有能力。
2. 把人物和场景从文字配置升级为真实资产生产。
3. 让镜头消费明确版本。
4. 把生成、审核和费用收敛到镜头级。
5. 将超管功能拆成默认不占空间的生产概览，以及按需打开的关系画布。
6. 复用现有服务，逐步删除旧 UI 和重复状态。

只有完成 M0–M6 并删除旧重复实现，才算整个剧情广告模块优化完成。
