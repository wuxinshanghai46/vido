## 2. 最重要的结论

VIDO 当前最需要修正的不是某一句视频提示词，而是生成链路的输入层级。正确流程不是：

`文学剧本 → AI 直接翻译成分镜 → 逐镜抽视频 → QA 不过再抽`

而应该是：

`故事理解 → 角色内核 → 单集目标 → 事件 → 剧情颗粒 → 资产合同 → 镜头功能 → 静态关键帧合同 → 动态合同 → 低成本预演 → 付费生成 → QA/修复 → 连续性合成`

参考视频给出的三个核心动作是：

1. 提炼角色内核，建立全局人设字典，而不是只摘取外貌。
2. 把长文本逐级降维为“单集 → 事件 → 分镜”，避免一次把全文交给模型。
3. 把分镜细节与角色图、场景图等资产绑定，再生成精准画面。

配套视频进一步强调：拆剧本的本质是把文学敲碎成演员可以执行的“剧情颗粒”；运镜、光影和情绪属于做视频阶段，不应过早混入剧情拆解。

## 3. 什么叫“剧情颗粒”

剧情颗粒不是镜头，也不是一句画面提示词。它是一个可执行、可验证、可承接的最小戏剧动作，至少包含：

- 谁在行动；
- 为了什么；
- 对谁或什么行动；
- 行动前状态；
- 可见动作；
- 行动后状态变化；
- 观众此刻应获得的信息或情绪；
- 与前后颗粒的因果关系。

例如原文“她被冰冷的金属震撼，缓缓伸手触摸墙面”不能立刻变成“中景、50mm、慢推”。更合理的拆法是：

1. 她停在墙前，视线被表面纹理吸引；
2. 她确认材质后抬手；
3. 指尖接近并触碰同一块连续表面；
4. 触感使她的表情或呼吸发生细小变化；
5. 叙事焦点从人物反应转向材质价值。

镜头设计随后再决定哪些颗粒可以共用一个连续镜头、哪里必须切换景别，以及切换服务于什么信息。

## 4. VIDO 应采用的七层拆解模型

### 4.1 故事层：先回答“这段为什么存在”

- 广告目标、受众和唯一卖点；
- 本集冲突、转折和结尾承诺；
- 每个事件对转化的作用；
- 删除该事件后故事是否仍成立。

没有叙事功能的镜头不进入付费生成队列。

### 4.2 角色层：全局角色合同

角色字典至少应包含：

- 身份、欲望、恐惧、秘密、关系；
- 稳定外貌和不可变特征；
- 当前服装、发型、饰品及其生效区间；
- 表演边界、微表情、惯用动作；
- 可出镜的身体部位与身份参考图；
- 角色在事件前后的心理状态。

角色合同需要版本号。已经批准的角色资产不能因为后续某个镜头的临时提示词而被悄悄改写。

### 4.3 事件层：一段只解决一个戏剧问题

长文本先切单集，再切事件。每个事件记录：

- 进入条件；
- 冲突或信息缺口；
- 关键动作；
- 状态改变；
- 离开条件；
- 必须继承到下一事件的资产与空间状态。

### 4.4 剧情颗粒层：演员可以执行

每个颗粒应使用“主体 + 动作 + 对象 + 结果”的可观察表达，禁止把“高级、震撼、电影感”当成动作。一个颗粒中不要同时塞入多个互相竞争的主动作。

### 4.5 镜头骨架层：先定功能，再定术语

镜头字段应按以下顺序生成：

1. 叙事功能：建立、揭示、反应、转折、证据、收束；
2. 主体与信息焦点；
3. 与前后镜头的承接点；
4. 景别和构图；
5. 镜头运动；
6. 时长；
7. 光影和情绪。

作者反复强调的“抽骨架 → 换皮 → 再激活”，本质是先从竞品中提取镜头功能、景别节奏、运动方向和切换逻辑，再换成自己的角色与场景资产，最后按自己的剧情重新激活动作；不是猜竞品用了哪句提示词。

### 4.6 资产合同层：把引用从文字变成 ID

提示词中的“参考图 1”属于弱引用。系统应保存明确的资产绑定：

- `character_asset_id`；
- `wardrobe_asset_id`；
- `location_asset_id`；
- `surface_asset_id`；
- `prop_asset_id`；
- `approved_keyframe_id`；
- `continuity_block_id`。

资产要记录视角、光照、适用景别、人物数量、空间拓扑和禁止变化项。真实照片或经过审核的关键帧是高信噪比物理参考，通常比抽象姿态骨架更能表达重力、肌肉张力和空间关系。

### 4.7 生成合同层：静态与动态分离

付费生成前必须同时通过两份合同：

- 静态关键帧合同：人物、服装、场景几何、材质拓扑、道具位置、构图；
- 动态合同：起始动作、结束动作、镜头方向、速度、可见身体部位、禁止新增内容。

视频模型不应重新设计已经批准的静态世界。它只负责在合同允许的范围内补全时间变化。

## 5. 为什么现有失败会像“抽卡”

当前失败大致分为四种，不能统一用“再生成一次”处理：

| 类型 | 例子 | 正确动作 |
|---|---|---|
| 输入合同矛盾 | 关键帧有人，规则却禁止出现人体 | 修复元数据或审核规则，0 次生成 |
| 资产信息不足 | 只写“参考图 1”，没有主体/场景绑定 | 补资产合同后再提交 |
| 模型能力边界 | 复杂入镜、精确手部、多人遮挡 | 拆动作、换模型或改为局部编辑 |
| 结果轻微偏差 | 可用视频只有局部瑕疵 | 编辑、裁切、局部重绘或人工接受 |

盲目重抽的问题是：输入不变时，系统只是在重复采样同一个错误分布。一次通过率不会因为按钮叫“修复”就自然上升。

## 6. 真正节省成本的生成策略

### 6.1 生成前四道门

1. 剧情门：颗粒是否单一、可执行、因果完整；
2. 资产门：人物、场景、材质、道具是否全部绑定；
3. 合同门：静态与动态要求是否冲突；
4. 计费门：预计付费任务数、时长、模型和最坏成本是否确认。

任何一道未通过都不能进入供应商队列。

### 6.2 生成方式按成本排序

1. 复用已通过素材；
2. 复审已有失败素材；
3. FFmpeg 确定性运镜、裁切、变速或转场；
4. 对已有视频做局部编辑；
5. 按连续场景组生成；
6. 最后才是单镜头重新生成。

### 6.3 默认零自动重试

一次供应商任务结束后，无论 QA 是否通过，都不自动再次付费。系统必须给出：失败类型、修改后的合同差异、预计新增成本和明确的人工确认入口。

### 6.4 衡量“可用秒”，不要只看单次价格

应追踪：

- 首次生成可用率；
- 每个可用镜头的平均付费任务数；
- 每个可用视频秒的真实成本；
- 供应商排队时间和结果过期率；
- 因输入合同矛盾造成的无效调用数；
- 复审、编辑和本地处理节省的任务数。

## 7. 如何做出竞品那种顺畅切换

顺畅不是最后给所有镜头套淡化。竞品效果通常来自前期镜头设计和同一连续场景内的动作承接。

### 7.1 连续场景组

同一空间、角色、服装、时间、光线和动作轴线的镜头组成一个 `continuity_block`。优先一次生成较长母片，再从母片切出多个镜头。这样比六次独立生成更容易保持人物、墙面和光线一致。

### 7.2 每个切点都要有承接字段

- 动作承接：前镜动作的落幅对应后镜动作的起幅；
- 视线承接：看向方向和被看对象一致；
- 运动承接：镜头或主体方向不突然反转；
- 构图承接：主体位置变化有意图；
- 音频承接：环境声连续，旁白用 J-cut/L-cut 提前或延后跨镜；
- 曝光与色彩承接：白平衡、亮度和材质色不跳变。

### 7.3 转场只在叙事需要时使用

- 同一动作：硬切或动作匹配切；
- 同一空间的时间推进：短溶解；
- 明确段落变化：淡入淡出；
- 同一连续母片：无缝切分，不叠加转场；
- 不用转场遮盖人物、材质或空间不一致。

### 7.4 合成前做连续性 QA

除了逐镜 QA，还要检查镜头对：末帧与下一镜首帧的人物身份、服装、空间、主色、运动方向、动作相位和音频底噪。只有逐镜通过、镜头对也通过，才进入第五步最终合成。

## 8. 对 VIDO 当前实现的判断

今天已经落地的成本预检、零自动重试、失败视频优先复审、确定性本地运镜、连续场景组、逐镜状态展示和“第四步生成/第五步只合成”都是正确基础。

仍需补齐的关键层不在按钮，而在数据模型与生成前规划：

1. 当前分镜结构仍偏“画面描述”，需要新增剧情颗粒和镜头功能；
2. 角色、服装、场景、材质和道具需要稳定资产 ID，而不是仅依赖自然语言；
3. QA 规则要从同一份静态/动态合同生成，避免关键帧与审核条件互相打架；
4. 生成前应展示“输入发生了什么变化”，没有变化就禁止用“修复”名义重抽；
5. 连续性要从单镜头状态升级为镜头对和连续场景组状态；
6. 失败后应优先建议可执行修复，而不是把提示词编辑责任交给普通用户。

## 9. 建议的产品流程

### 第 1 步：广告需求

只确定受众、目标、卖点、时长、风格边界和禁用项。

### 第 2 步：故事与资产配置

创建角色内核字典、场景/材质/道具资产，并确定版本。

### 第 3 步：剧本生成

先展示单集事件和剧情颗粒，再由系统生成镜头骨架。用户审核的是故事逻辑和信息节奏，不是复杂视频提示词。

### 第 4 步：分镜与逐镜视频

先生成并审核静态关键帧；系统自动生成动态合同和成本预检；用户看到“复用、复审、本地处理、付费生成”四类计划，再确认生成。每个镜头在本页播放、审核、接受或定向修复。

### 第 5 步：广告合成

只使用第四步已经通过或人工接受的镜头，处理剪辑、旁白、字幕、音乐、响度和转场；绝不在这里隐式生成新视频。

## 10. 下一轮开发优先级

### P0：先停止无意义重抽

- 增加“修复前后合同差异”；无差异则禁止付费重做；
- 为失败原因建立确定性分类和处置建议；
- 将剧情颗粒、镜头功能、起幅和落幅加入分镜数据；
- 从同一合同派生提示词与 QA 规则。

### P1：提高一次通过率

- 角色/场景/材质资产注册表及版本绑定；
- 自动检测人物数量、身体部位、场景拓扑和动作冲突；
- 连续场景组母片规划和镜头切片；
- 镜头对连续性 QA。

### P2：逼近竞品完成度

- 竞品视频自动切镜，提取“镜头骨架”而非照抄提示词；
- 结构换皮后重新绑定 VIDO 自有资产；
- J-cut/L-cut、动作匹配切、响度和色彩匹配自动化；
- 用“每个可用秒真实成本”和“首次可用率”做运营看板。

## 11. 验收指标

下一轮优化不应以“按钮能点”验收，而应以：

- 生成前合同冲突拦截率 ≥ 95%；
- 自动付费重试数 = 0；
- 输入未变化时的重复生成数 = 0；
- 首次生成可用率持续上升；
- 每可用秒成本持续下降；
- 逐镜通过后，镜头对连续性通过率可量化；
- 第五步供应商视频生成调用数 = 0。

## 13. 一句话产品原则

**让用户确认故事、资产和成本，让系统负责把它们编译成提示词、QA 和连续镜头；不要让用户用付费抽卡来替系统调试。**
